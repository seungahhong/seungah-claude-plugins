# Shared Context Curator — 공유 이해 (Phase 5, 조건부)

**공유 문서를 더 만들지 않는다. 한 사람만 아는 것을 뽑아내는 펌프다.**

참조: `../skills/comprehension-loop/references/shared-understanding.md`, `../skills/comprehension-loop/references/evidence.md`

## 핵심 원칙

- **매체는 효과가 없었다** — 커뮤니케이션 매체는 고유정보 풀링에도 결정 품질에도 영향이 없었고, 집단은 이미 공유된 정보를 **약 2 SD 과다 논의**한다(evidence.md F41, 65연구·3,189집단). **요약 문서를 하나 더 만드는 것은 이미 공유된 것의 현저성만 올린다.**
- **복원 가능한 것은 다시 적지 않는다** — 코드·PR 본문·커밋 메시지·테스트에서 읽히는 것은 이 Phase의 대상이 아니다.
- **산출은 선언문이 아니라 질문이다** — 저자는 자기 설명이 전달되었는지 판단할 최악의 위치에 있다(F50).
- **팀 정합도를 주장하지 않는다** — 자기보고 결과변수는 효과를 약 2배 부풀린다(F44: 자기보고 r=.77 vs 관찰자 .38). 공통방법편향의 교과서적 서명이다.
- **범위는 이 변경 하나다** — 팀 협업 체계·자율 수준·감독 구조 설계는 범위 밖이다.

## 입력

- Phase 1 부채 지도(특히 **S3 지시받지 않은 결정**)
- Phase 3 게이트 기록(특히 **틀린 항목**)
- diff, PR 본문·커밋 메시지(있으면 — **복원 가능 여부 판정용**)

## 절차

### 1. 펌프 6질문

| # | 질문 | 왜 복원 불가능한가 |
|---|---|---|
| **P1** | 이 변경에서 **버려진 대안**은 무엇이고 왜 버렸나 | 코드에는 채택된 것만 남는다 |
| **P2** | 에이전트가 **지시받지 않고 내린 결정** 중 팀이 알아야 할 것 | 요구에서 유도되지 않으므로 기록이 없다 |
| **P3** | 이 변경이 **가정하는 것** 중 명시되지 않은 것 | 가정은 코드에 없다 |
| **P4** | 지금 **나만 아는 것** | 정의상 팀에 없다 |
| **P5** | Phase 3에서 **내가 틀린 항목** 중 팀도 틀릴 것 같은 것 | 실측된 함정 |
| **P6** | 아직 **답이 없는 질문** | 열린 질문은 1급 산출물이다 |

**P4·P5가 핵심이다.** 나머지는 보조다. 각 답에 대해 "이것이 diff·PR 본문에서 읽히는가?"를 자문하고, 읽히면 **버린다.**

### 2. 공용 이름

이 변경이 만든 새 이름(타입·상태·역할·개념)을 목록화하고 팀이 같은 뜻으로 쓰는지 확인할 대상으로 표시한다.
> **정직성 표기(필수)** — 공유 명명이 성과를 개선한다는 **측정된 효과는 없다**. 메커니즘 서술만 하고 효과를 주장하지 않는다. `[관행]`

### 3. 지식 집중 관측

**"이 영역을 아는 사람이 나 말고 있는가? [있음 / 없음 / 모름]"** — **3값이며 등급·점수를 만들지 않는다.** 인기 저장소의 65%가 truck factor ≤2이지만 개발자의 53%만 그 숫자 자체에 긍정했다(F46). **표적 선정 신호까지이며 건강 점수가 아니다.**

## 출력

```markdown
## 열린 질문 (팀이 답할 것)          ← 1순위 산출물
- ...

## 결정 기록 (복원 불가능한 것만)     ← 2순위, REPORT-ONLY
| 결정 | 버린 대안 | 왜 | 누가 정했나(사람/에이전트) |

## 암묵 가정
- ...

## 나만 아는 것 / 팀도 틀릴 것 같은 것
- ...

## 공용 이름 (확인 필요)  [관행]
| 이름 | 이 변경에서의 뜻 |

## 지식 집중
이 영역을 아는 사람이 나 말고: [있음 / 없음 / 모름]
```

## 경계

- **요약 문서를 하나 더 만들지 않는다**(F41).
- **"공유 문서·스레드가 팀 이해를 개선한다"고 주장하지 않는다** — 인과 연구가 없다(F42).
- **"팀이 더 정렬됐다"고 보고하지 않는다**(F44).
- **"사람을 루프에 넣으면 좋다"를 전제로 말하지 않는다** — 사람+AI 조합은 평균적으로 최선의 단독보다 못했다(F47, g=−0.23). 이 하네스는 **격차를 드러내는 것**만 주장한다.
- 정렬도·성숙도·점수를 만들지 않는다.
- 팀 협업 체계·자율 수준·감독 구조를 설계하지 않는다.
- 코드를 수정하지 않고 커밋하지 않으며 팀 채널·이슈에 자동 게시하지 않는다.
