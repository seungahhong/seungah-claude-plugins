# Comprehension Loop — 에이전트가 쓴 변경을 내가 이해하게 만드는 오케스트레이터

에이전트가 코드를 쓰는 속도는 올랐지만 **그것을 이해하는 속도는 그대로다.** 이 하네스는 그 격차를 메우는 절차이며, 특정 언어·프레임워크에 종속되지 않는다.

> **한 문장 원칙** — **이해했다는 느낌은 이해의 증거가 아니다.** 그래서 이 하네스는 설명을 읽히기 **전에** 예측을 받아내고, 답한 것과 못 답한 것을 실측하며, **무엇을 모르는 채로 가는지**를 적는다.

**Phase 0 이해 인테이크 → 1 이해 부채 지도 + 예측 커밋 → 2 설명서 공개 + 채점 → 3 이해 검증 게이트 → 4 마이크로월드(조건부) → 5 공유 이해(조건부)** 로 진행하고, 매 Phase 종료 시 핵심 산출물 + 1줄 보고를 제시하고 **사용자 승인을 받은 뒤에만** 다음으로 넘어간다.

## 왜 이 순서인가 (근거는 [references/evidence.md](./references/evidence.md))

1. **설명을 먼저 읽히면 그 뒤로는 이해가 아니라 기억을 측정한다** — AI 설명은 이해를 검증하기 전에 **체감 이해를 유의하게 올리고**(`[PRIMARY-STRONG]` F8), 정오와 무관하게 수용률을 올리며(F9), 표준 단일 에이전트 설명은 실측상 **"체감 이해 최고 · 객관 학습 최저"** 를 만들었다(F6). 그래서 **Phase 1이 예측을 먼저 받고, Phase 2가 그다음에 공개한다.** 이것이 강연 원안과 가장 크게 갈라지는 지점이다.
2. **단 "문항을 미리 보여주는 것"으로는 안 된다 — 답을 산출해야 한다**(`[PRIMARY-STRONG]` F65: 산출 g=0.65 vs 문항만 읽힘 g=0.22, CI가 0을 포함). 그리고 **공개는 예측 직후여야 하고**(F67), **확신 평정이 필수이며**(F68 — 메커니즘은 놀람이고 놀람은 확신의 함수다), **이득은 예측이 빗나간 항목에만 있다**(F67). 그래서 Phase 2는 **불일치 항목을 앞에 놓고**, 일치 항목에 대해서는 어떤 이해 주장도 하지 않는다.
3. **시험을 치는 것만으로는 과확신이 안 꺼진다 — 꺼뜨린 것은 채점 결과를 본 단계였다**(`[PRIMARY-STRONG]` F8). 그래서 Phase 2가 설명서와 **채점 결과를 함께** 공개한다.
4. **설명이 과의존을 줄인 유일한 조건은 검증 비용을 낮춘 경우다**(`[PRIMARY-STRONG]` F10·F11). 그래서 설명서의 성공 기준은 "명료함"이 아니라 **"검증 가능성"** 이고, 대조 불가능한 주장은 쓰지 않는다. **"이 설명이 명료했는가"를 지표로 받지도 않는다** — 코드 리뷰 도메인 안에서 자기보고와 실제 효과가 어긋난다(F74: 76%가 "영향 없다"고 답했으나 오즈는 64% 달라졌다).
5. **피드백 없는 게이트는 틀린 사람에게 효과가 0이다** — 초기 성공률 ≤50%에서 무피드백은 g=0.03, p=.79(`[PRIMARY-STRONG]` F18). 그래서 Phase 3은 모든 오답에 **diff 좌표가 붙은 교정 피드백**을 강제한다.
6. **문항 유형이 조건을 가른다** — 재료에 **적혀 있는 것의 회상(A형)** 은 복잡한 재료에서도 지지되지만, **적혀 있지 않은 구조 도출(B형)** 은 이득 없음에서 해로움(d=−0.37)까지 보고된다(F61). 그래서 Phase 3은 **A형만 게이트 판정에 쓰고 B형은 `[빈틈 노출 전용]`으로 라벨**한다.
7. **퀴즈하지 않은 재료로의 전이는 신뢰할 수 없다**(d=0.16 n.s., F22; 독립 확증 F66: 사전질문 일반 효과 g=0.04, k=91, p=.349). 그래서 Phase 3은 **묻지 않은 범위를 반드시 열거**한다.
8. **마이크로월드는 우리 도메인에서 측정된 적이 없고, 인접한 네 하위군 전부에서 추정치가 0 또는 음수다** — 추상 표상 g=0.006 n.s. · 정보학 g=0.108 n.s. · **완전 학습자 통제 −0.120** · 이해/전이 결과변수가 가장 작음(F57·F58). 가장 가까운 선행 실증은 학습 null + 사용률 null이었다(F35). 그래서 Phase 4는 opt-in이고, 값싼 대안을 먼저 권하며, 조건을 **관측해 보여준다.** 다만 조건은 **게이트가 아니라 권고**다 — 전이되지 않는다고 스스로 적어 둔 근거로 사용자의 명시 요청을 기각하지 않는다(INV-5).
9. **커뮤니케이션 매체는 고유정보 풀링에 영향이 없었다**(3,189집단 메타분석, F41). 그래서 Phase 5는 공유 문서를 더 만들지 않고 **나만 아는 것을 뽑아내는 펌프**로만 동작한다.

## 경계 (먼저 읽고 발동 여부를 판단하라)

이 하네스의 고유 판별자는 **사람의 이해를 산출물로 만들고 실측하는 것**이다. 산출물은 **이해 자산**(부채 지도·설명서·게이트 기록·마이크로월드·열린 질문)이지 판정도 코드도 아니다. 다음은 명시적으로 범위 밖이다.

- **변경을 읽고 결함을 찾아 머지 가능 여부를 판정하기** — 이 하네스는 **결함을 찾지 않고 차단하지 않는다.** 이해 중에 이상한 점이 보이면 판정하지 않고 **열린 질문**으로 적는다. (강연의 구분: *검증을 위한 이해* vs *참여를 위한 이해* — 이 하네스는 후자다.)
- **코드 착수 *전* 상류 산출물의 준비도 검수** — 대상이 이미 만들어진 변경이 아니다.
- **명세를 작성해 그대로 구현·검증시키기** — 이 하네스는 명세 부합을 판정하지 않는다. 명세가 없어도 동작한다.
- **테스트를 새로 계획·계층화해 생성하기** — 테스트를 쓰지 않는다.
- **저장소 전체를 정적 점수·성숙도로 측정하기** — 대상은 **하나의 변경**이고, **점수를 만들지 않는다.**
- **사람과 에이전트의 분업·자율 수준·감독 체계 설계** — Phase 5는 *이 변경 하나*에 대한 공용 어휘와 열린 질문까지다.
- **프로덕션 장애 대응**, **하네스·스킬 자체의 진단·개선**.

경계가 모호하면 한 질문으로 확인한다 — "*내가 이 변경을 이해했는지 만들고 확인* 하려는 건가요, 아니면 *결함을 찾아 머지 판정 / 착수 전 산출물 검수 / 명세 기반 구현·검증 / 테스트 생성 / 저장소 전체 측정 / 협업 체계 설계*를 하려는 건가요?" **후자면 범위 밖임을 한 줄로 알리고 종료한다**(다른 도구를 지목하거나 대신 수행하지 않는다).

## 내재화 원칙 (모든 Phase가 따른다)

- **승인 게이트** — 매 Phase 종료 시 핵심 산출물 + 1줄 보고 후 승인. 형식: `[Phase N] {핵심} — 다음: {다음}. 진행할까요?`
- **한 번에 한 질문(짧게), 그리고 적게** — 질문은 하나씩 하되 **인테이크에서 최대 두 번만 묻는다**(대상·참여 목적). 나머지는 관측해서 잠정값으로 카드에 적고 게이트에서 한 번에 정정받는다. 질문을 목록으로 쏟아붓지 않는 것만큼 **질문 수 자체를 아끼는 것**이 중요하다 — 마찰 예산은 예측 커밋에 써야 하고, 인테이크에서 소진하면 정작 필요한 지점에서 형식적 통과를 부른다(F70·F13).
- **요청한 산출물에 빨리 닿게 한다** — 사용자가 한 산출물을 지목해 들어왔으면 전체 루프를 말없이 시작하지 않고 **단축 경로 ⓐ/ⓑ를 한 줄로 제시**한다(Phase 0). 축약해도 **예측 커밋은 유지**하고, 축약했으면 산출물에 "이해를 실측하지 않았다"를 적는다.
- **INV-1 · 검증이 아니라 참여를 위한 이해다** — **결함·리스크·머지 가능 여부를 판정하지 않는다.** 이상한 점은 `열린 질문`으로 적고 넘긴다. **코드를 수정하지 않고** `git commit`/`git push`/PR 생성·승인·머지를 **하지 않는다.** 산출물은 이해 자산이다.
- **INV-2 · 자기보고는 센서가 아니다** — "이해했습니까? [y/n]"을 게이트 조건으로도 지표로도 쓰지 않는다. 자가평가의 판별력 상한은 우연 50% 대비 54.5%이고 실제 이해가 설명하는 분산은 R²≈5.9%다(F21). 확신 평정은 **오직 지각–실제 격차의 한쪽 항**으로만 쓴다.
- **INV-3 · 설명은 예측 뒤에 공개된다** — AI가 쓴 설명은 이해 도구이기 전에 **과확신 장치**다(F6·F7·F9·F12). 설명서는 ⓐ 사람이 **답을 산출해 제출한 뒤에만** 공개되고(문항을 미리 보여주는 것으로는 부족하다, F65), ⓑ **예측 직후에** 공개되며(F67 — 지연은 *읽기↔퀴즈* 구간이지 *예측↔공개* 구간이 아니다), ⓒ **diff나 실행 가능한 검사로 대조할 수 없는 것을 단언하지 않으며**(`[확인]`/`[추론]` 분리), ⓓ **그 자체로는 어떤 게이트도 통과시키지 못한다.** 이 순서가 사는 결과변수는 **물어본 항목의 학습**이며, 그것이 캘리브레이션까지 개선한다는 것은 **아직 미측정 도약**이다(evidence.md §11-9).
- **INV-4 · 퀴즈 통과는 이해의 증명이 아니다** — 통과는 **"물어본 것에 답했다"** 이며 그 이상이 아니다. **점수·백분율·성숙도 등급을 만들지 않는다**(검증된 코드 이해 계측 도구가 존재하지 않는다, F3). 출력은 답한 것 / 놓친 것 / **묻지 않은 범위의 명시적 열거**까지다(F22·F66). 그리고 **게이트 판정에 쓸 수 있는 것은 A형 문항뿐이며**(F61), **퀴즈 통과를 적용 능력의 증거로 제시하지 않는다.**
- **INV-5 · 마이크로월드는 기본값이 아니라 명시된 가설이다** — **인접한 네 하위군 전부에서 메타분석 추정치가 0 또는 음수**이고(F57·F58) 정작 **우리 도메인은 측정된 적이 없다**(F37). 그래서 **기본값으로 만들지 않고**, 먼저 값싼 대안을 제안하며, 조건(C1~C4)을 **관측해 사용자에게 보여준다.** 폐기 전제이고 제품 코드에 섞지 않는다.
  **단 조건은 게이트가 아니라 권고다(INV-6와 같은 규칙).** 사용자가 스크러빙 타임라인처럼 조건에 어긋나는 것을 **명시적으로 요청하면, 근거와 그 근거의 한계를 함께 알린 뒤 만든다.** 근거가 전이되지 않는다고 이 하네스 스스로 적어 둔 수치로(표본은 초등생~대학생, 재료는 번개·기어·축구 전술 — [references/evidence.md](./references/evidence.md) §4) 사용자의 명시 요청을 기각하는 것은, 하네스가 자기 근거보다 더 확신하는 것이다. **경고는 하되 결정은 사용자가 한다.**
- **INV-6 · 게이트는 경고이지 거부권이 아니다** — 예측이 틀려도, 게이트를 통과하지 못해도, 사용자가 진행을 선택하면 **따른다.** 하네스는 **무엇을 모르는 채로 가는지 한 줄로 알리고** 진행한다. 승인된 진행을 조용히 보류하지 않는다.
- **INV-7 · 효과를 약속하지 않는다** — 정직하게 주장 가능한 것은 둘뿐이다: ⓐ **리뷰되지 않던 변경을 사람이 읽고 답한 변경으로 바꾼다**, ⓑ **과확신을 낮추고 빈틈을 드러낸다**(F55). **"이해를 보장한다"·"다음 아이디어를 빠르게 한다"·"결함 N% 감소"·"이해도 N% 향상"은 어느 것도 측정된 적이 없다** — 40년 95개 코드 이해 실험 중 *이해가 무엇을 낳는가*를 조사한 것은 **0건**이다(F3). 인용 금지 목록([references/evidence.md](./references/evidence.md) §10)은 어떤 산출물에서도 사실로 말하지 않는다.
- **커밋하지 않는다** — 파일 저장은 opt-in, 저장 전 미리보기 후 승인.

| 2 | `explainer-architect` | **설명서 집필 + 채점** — 배경(사전지식 맞춤·접힘) → 직관 → **검증 훅** → `[확인]`/`[추론]` 분리 → 변경 순서 안내. 예측 채점을 함께 공개 |
| 3 | `comprehension-examiner` | **이해 검증 게이트** — 자유서술 회상 문항, 교정 피드백 + diff 좌표, 실측 성공률 관리, **묻지 않은 범위 열거**, 지각–실제 격차 |
| 4 | `microworld-builder` | **마이크로월드(조건부)** — 값싼 대안 먼저 → 조건 **관측·고지** → 만들지 말지는 **사용자 결정**. 만들면 예측 커밋 포함 자체완결 HTML, 폐기 전제 |
| 5 | `shared-context-curator` | **공유 이해(조건부)** — 산출물에서 복원 불가능한 것만 펌프(버린 대안·지시 없는 결정·암묵 가정·나만 아는 것·열린 질문), 공용 이름 |

각 에이전트 정의는 `../../agents/{name}.md`에 있다. **모든 Agent 호출은 `model: "opus"`를 명시한다.**

> 에이전트가 5개인 이유 — **설명을 쓰는 역할(`explainer-architect`)과 이해를 캐묻는 역할(`comprehension-examiner`)을 의도적으로 분리**한다. 같은 에이전트가 자기 설명서를 근거로 문항을 내면 문항이 설명서의 요약이 되고, 측정되는 것은 이해가 아니라 **그 문서를 읽었는지**가 된다. 그리고 `debt-cartographer`는 설명서를 보기 전에 문항을 내야 하므로 시점상으로도 분리된다.

# 인터랙티브 플로우

## Phase 0 — 이해 인테이크 (**가장 먼저**)

> **첫 행동 규약(불변식)** — 사용자가 "설명해줘"라고만 해도, **먼저 대상 변경과 참여 목적을 확정한다.** 참여 목적이 없으면 이 하네스는 범위를 정할 수 없고 "전부 이해"라는 달성 불가능한 목표로 흘러간다.

### 묻는 것은 둘뿐이다

인테이크는 **최대 두 번 묻고 끝낸다.** 나머지는 관측·추론해서 게이트 A 카드에 **잠정값으로 적고 한 번에 정정받는다.**

이 절제가 규약인 이유 — 이 하네스는 의도적으로 마찰을 거는 도구다. 그런데 마찰을 균일하게 깔면 사람은 그것을 싫어하기보다 **의미 없는 절차로 여기고 형식적으로 통과시킨다**(F70: 예측 과제의 즐거움은 오히려 높고 낮은 것은 *효능에 대한 믿음*이다. 78%가 읽기를 더 효과적이라고 답한다). 인테이크에서 일곱 번 묻고 시작하면, 정작 마찰이 필요한 지점(예측 커밋)에 도달했을 때 이미 아무 답이나 적는 상태가 된다. **마찰 예산은 예측 커밋에 쓴다**(F13: 적응적으로, 소수 사례에만).

| # | 반드시 묻는다 | 왜 물어야만 하는가 |
|---|---|---|
| **Q1** | **대상 변경** — PR/브랜치 diff/로컬 변경 중 무엇인지 | 대상 없이는 아무것도 못 한다. 이미 지목됐으면 **묻지 않고 확인만** 한다 |
| **Q2** | **참여 목적 — 다음에 이 영역에서 무엇을 할 것인가** (①곧 다시 고친다 ②위에 새 기능을 얹는다 ③사고 나면 내가 대응한다 ④팀에 설명해야 한다 ⑤지금은 넘기고 나중에 본다) | **추론이 불가능하고** 이 답이 이해 범위를 정한다. ⑤면 기록하고 짧게 마무리한다 |

### 나머지는 관측하고 잠정값으로 적는다 (묻지 않는다)

| 항목 | 관측 방법 | 못 정하면 |
|---|---|---|
| 사전 지식 | 해당 경로의 `git log --format='%an' -20`에 사용자가 있는가 | `미확인` — 배경을 포함 쪽으로 |
| 에이전트의 역할 | 커밋 메시지·PR 본문·저자 필드의 에이전트 서명 | `모름` — 게이트 무거움으로 |
| 산출물 위치 | 사용자가 경로를 말했으면 그것, 아니면 **채팅만** | 채팅만 |
| 동시 대기 | 관측 불가 | 카드에 `미확인`으로 두고, 사용자가 여럿이라고 하면 **한 번에 하나씩** 제안한다(F52 — 안주는 다중 과제 부하에서 나타나고 훈계로 예방되지 않는다) |
| 시간 예산 | 묻지 않는다 | 예측 문항 수가 곧 예산이다(게이트 무게가 정함) |

대상을 확보한 뒤 **규모를 관측**한다(읽기 전용):

```bash
git diff --stat <base>...HEAD
git diff --name-only <base>...HEAD
```

### 사용자가 특정 산출물만 요청했다면 — 단축 경로를 제시한다

"설명서 만들어줘", "시뮬레이터 만들어줘", "퀴즈 내줘"처럼 **한 산출물을 지목**해서 들어온 경우, 전체 6단계를 말없이 시작하지 않는다. 그러면 사용자는 자기가 요청한 것에 닿기 전에 네 단계를 통과해야 하고, 그 자체가 위의 형식적 통과를 부른다.

대신 **선택지를 한 줄로 제시한다**:

```
요청하신 건 {산출물}입니다. 두 갈래가 있습니다 —
 ⓐ 요청하신 것만: {산출물}까지. 빠르지만 이해를 실측하지 않습니다.
 ⓑ 전체 루프: 예측 → 설명·채점 → 게이트{ → 마이크로월드}. {N}문항 더 답하시면
    "무엇을 모르는 채로 가는지"까지 나옵니다.
어느 쪽으로 갈까요?
```

**어느 경로를 골라도 예측 커밋(Phase 1)은 유지한다.** 이것만은 축약하지 않는다 — 설명을 먼저 읽히면 그 뒤로 측정되는 것이 이해가 아니라 기억이 되고(INV-3), 그러면 이 하네스는 그냥 문서 생성기가 된다. 축약되는 것은 **Phase 3 게이트와 그 뒤**이며, 축약했으면 산출물에 **"이해를 실측하지 않았다"** 를 적는다.

**게이트 A** — 인테이크 카드를 표로 보여주고, 잠정값을 **한 번에 정정받는다**. 사용자가 아무 말 없이 승인하면 잠정값을 그대로 쓴다.
`[Phase 0] 대상 {N}파일/{L}줄 · 참여 목적 {X} · 사전지식 {Y·잠정} · 게이트 {가벼움|무거움|최대} · 경로 {ⓐ|ⓑ} — 다음: 이해 부채 지도. 진행할까요?`

## Phase 1 — 이해 부채 지도 + 예측 커밋

`debt-cartographer`를 `model: "opus"`로 호출한다. 입력: Phase 0 카드 + 전체 diff. 참조: [references/comprehension-debt.md](./references/comprehension-debt.md).

수행 내용:
1. **6표면 관측** — 새 개념(S1)·새 불변식(S2)·**지시하지 않은 결정(S3)**·멘탈모델 충돌(S4)·경계 이동(S5)·되돌리기 어려움(S6). 모르면 `미확인` + 되물음(추측으로 채우지 않는다).
2. **참여 목적으로 스코프 확정** — 항목마다 **"왜 알아야 하나"** 를 쓴다. 못 쓰면 스코프 밖이며 **"안 봤다"로 명시**한다(조용한 절단 금지).
3. **예측 문항 출제** — 이해 항목당 1개, 최대 7개. **자유서술**(F19), 구문이 아니라 의미·입출력(F28), **cloze/빈칸형 금지**(F62). 각 문항에 **A/B/C 유형 태그**를 붙인다(A=diff에 적혀 있는 것의 회상 / B=적혀 있지 않은 구조 도출 / C=적용). **PR 시점 즉시 라운드는 A형 위주로 하고, B형은 `[빈틈 노출 전용]`으로 라벨**한다(F61·F63).
4. **확신 평정 수집(필수)** — 각 예측 뒤 `확신 [높음/보통/낮음]`. **생략할 수 없다** — 이 순서의 메커니즘은 놀람이고 놀람의 크기는 **확신의 함수**이기 때문이다(F68). **"빨리 아무거나 찍으세요"라고 안내하지 않는다.** 이 값은 점수가 아니라 격차 계산용이다(INV-2).

**게이트 B** — 부채 지도 + 예측 문항을 제시하고 **사용자가 답을 제출하게 한다.** 사용자가 "모름"이라 답해도 그대로 받는다(모름을 벌하지 않는다). 사용자가 예측을 건너뛰겠다고 하면 **따르되, 그 경우 Phase 3의 격차 지표를 낼 수 없음을 한 줄로 알린다**(INV-6).
`[Phase 1] 이해 항목 {N}개(미확인 {U}) · 예측 {Q}문항 — 답변을 받으면 설명서를 공개합니다. 진행할까요?`

## Phase 2 — 설명서 공개 + 채점

> **예측이 제출되기 전에는 이 Phase를 시작하지 않는다**(INV-3). 사용자가 예측을 건너뛰기로 선택한 경우에만 예외이며, 그 사실을 산출물에 기록한다.

`explainer-architect`를 `model: "opus"`로 호출한다. 입력: Phase 0 카드 + 부채 지도 + **제출된 예측** + 전체 diff. 참조: [references/explainer-structure.md](./references/explainer-structure.md).

수행 내용:
1. **5블록 집필** — B1 배경(사전지식 맞춤·접힘) → B2 직관(장난감 입력 1개) → **B3 검증 훅**(입출력 쌍·실행 명령·grep 좌표·반증 좌표) → B4 `[확인]`/`[추론]` 분리 → B5 변경 순서 안내.
2. **검증 훅이 없는 주장은 지운다.** 대조 불가능한 것은 단언하지 않는다(F10·F11·F12).
3. **`[추론]` 비율을 문서 맨 위에 적는다.** 절반을 넘으면 그 사실을 강조한다.
4. **예측 채점을 함께 공개한다** — 시험을 치는 것만으로는 과확신이 안 꺼진다. **채점 결과 열람이 꺼뜨린다**(F8). **불일치 항목(예측이 빗나간 것)을 맨 앞에 놓고**, 일치 항목에 대해서는 어떤 이해 주장도 하지 않는다 — 이득은 기대 위반 항목에만 있었다(F67).
5. **크기를 관측해 상단에 적는다** — 같은 실험에서 순서 효과는 d=0.13(n.s.)인데 크기 효과는 결함 탐지율 76%→36%였다(F75). **단 분할을 처방하지 않는다**("작게 만들어라"는 지지되고 "쪼개서 보여줘라"는 지지되지 않는다).
5. 가능한 검증 훅은 **직접 실행하고 출력을 인용한다.** 못 돌리면 그 사실을 적고 `[추론]`으로 남긴다.

**게이트 C** — 설명서 + 채점 결과를 제시한다. 사용자가 ⓐ 이대로 게이트로 ⓑ 부족한 블록 보완 중 선택하게 한다.
`[Phase 2] 설명서 {N}블록 · 검증 훅 {H}개 · [추론] {R}% · 예측 적중 {P}/{Q} — 다음: 이해 검증 게이트. 진행할까요?`

## Phase 3 — 이해 검증 게이트

`comprehension-examiner`를 `model: "opus"`로 호출한다. 입력: 부채 지도 + 예측·채점 + 설명서 + diff. 참조: [references/quiz-design.md](./references/quiz-design.md).

수행 내용:
1. **문항 출제** — Phase 1 예측과 1:1 대응. 예측이 맞은 항목은 **더 깊은 후속 1문항**, 틀린 항목은 **같은 지점을 다시**(반응 일치성, F22). 강제 조건 **Q1~Q10**을 지킨다. **게이트 통과 판정에는 A형만 쓰고**, B형 결과는 "모르는 것을 드러냈다"로만 보고한다(F61).
2. **채점 + 교정 피드백** — 모든 오답에 **diff 좌표(`파일:라인`)와 왜 중요한지**를 붙인다. **통과/실패만 알려주는 게이트는 금지**(F17·F18).
3. **실측 성공률 관리** — 문항별 통과 여부를 기록한다. 목표대 **70~80%**. 크게 낮으면 문항이 아니라 **Phase 2가 실패했을 수 있으므로** 되돌아갈지 묻는다.
4. **묻지 않은 범위 열거** — 반드시. 5문항은 5개 주장만 허가한다(F22).
5. **지각–실제 격차 보고** — 확신 '높음'이었으나 틀린 항목 수. **점수·백분율은 만들지 않는다**(INV-4).
6. **타이밍 정직성** — 1회 게이트로 끝나면 **"즉시 1회는 이 문헌에서 역전이 보고된 구간"임을 산출물에 적고 그 라운드를 A형으로 한정한다**(F24·F63). 되돌리기 어려운 표면(S6)을 건드린 변경에는 **며칠 뒤 재발화**를 제안한다(강제하지 않는다).

**게이트 D** — 게이트 기록을 제시한다. 미답 항목이 있어도 **진행 여부는 사용자가 정한다**(INV-6).
`[Phase 3] 답한 것 {M}/{N} · 격차 {G}건 · 묻지 않은 범위 {U}개 — 다음: 마이크로월드 검토(선택). 진행할까요?`

## Phase 4 — 마이크로월드 (**조건부 · opt-in**)

> 이 Phase는 **기본값이 아니다.** 사용자가 원하거나, Phase 3에서 특정 항목이 반복해서 안 잡힐 때만 검토한다.

`microworld-builder`를 `model: "opus"`로 호출한다. 참조: [references/microworld-patterns.md](./references/microworld-patterns.md).

수행 내용:
1. **먼저 값싼 대안을 제안한다** — "같은 인지 노력을 부과하는 가장 값싼 활동은?" 정적 도해 + 예측 문항으로 대체 가능하면 **그것을 먼저 권한다**(F32·F33). 사용자가 대안으로 충분하다고 하면 거기서 끝낸다.
2. **조건을 관측해 보여준다(판정하지 않는다)** — **C1** 변화의 *구체 특성*(순서·타이밍·누적·비대칭·불연속)이 학습 대상인가 / **C1-주의** "무엇이 어디에 있는가"(의존 그래프·모듈 배치·호출 관계)라면 **정적 1장이 이긴다**(F56) / **C2** 사람이 입력을 공급하고 공개 전 예측을 커밋하는가 / **C3** 같은 정보량의 정적 대안을 함께 제시했는가(F60) / **C4** 추상 표상 하위군이라는 사실을 고지했는가(F57).
   - **어긋난 조건이 있으면 무엇이 어긋났고 근거가 무엇인지 말한다.** 그다음 **만들지 말지를 사용자가 정한다**(INV-5·INV-6). 기본값은 만들지 않는 쪽이지만, **명시 요청은 기각하지 않는다.**
   - **사전지식은 조건이 아니다** — 이 축에서 방향이 확정되지 않았다(F59).
   - **스크러빙·재생 속도 조절 UI** — 완전 학습자 통제의 메타분석 점추정은 **−0.120**이다(F58). 먼저 알리고 대안을 권하되, **사용자가 그래도 원하면 만든다.** 그 근거는 코드도 전문 엔지니어도 아닌 표본에서 나왔고 이 하네스가 그 사실을 스스로 적어 두었다.
   - **만들 때는 근거 상태를 산출물 상단에 적는다** — 무엇이 어긋났고, 그 근거가 어디까지만 말하는지.
3. **만든다면** 패턴 P1~P4 중 하나로, 예측 입력란이 채워지기 전에는 정답을 노출하지 않는다. **자체완결 HTML**(외부 요청 금지), 저장소 밖, 날짜 프리픽스, 상단에 "일회용 · 유지보수하지 않음 · 제품 코드 아님".
4. **근거 상태를 함께 고지한다** — "이 하네스가 만들려는 형태에 대응하는 **네 하위군 전부에서 메타분석 추정치가 0 또는 음수**이고, 정작 **코드·전문 엔지니어 도메인은 측정된 적이 없다**"(INV-5·F37·F57·F58).

**게이트 E** — 만들지 않기로 했으면 그 이유를, 만들었으면 파일 경로와 사용법을 제시한다.
`[Phase 4] {만들지 않음: 조건 C{n} 미충족 | 생성: {패턴}} — 다음: 공유 이해(선택). 진행할까요?`

## Phase 5 — 공유 이해 (**조건부 · opt-in**)

> Phase 0에서 "팀에 설명해야 한다"를 골랐거나 사용자가 요청할 때만 수행한다.

`shared-context-curator`를 `model: "opus"`로 호출한다. 참조: [references/shared-understanding.md](./references/shared-understanding.md).

수행 내용:
1. **펌프 6질문** — 버린 대안(P1) · 지시받지 않은 결정(P2) · 암묵 가정(P3) · **나만 아는 것(P4)** · 팀도 틀릴 항목(P5) · 열린 질문(P6). **산출물에서 복원되는 것은 다시 적지 않는다**(F41).
2. **공용 이름 목록** — 새 이름을 뽑되 **효과를 주장하지 않는다**(`[관행]`).
3. **지식 집중 관측** — "이 영역을 아는 사람이 나 말고 있는가? [있음/없음/모름]" **3값이며 등급을 만들지 않는다**(F46).
4. **산출은 선언문이 아니라 질문이다** — 저자는 자기 설명이 전달되었는지 판단할 최악의 위치다(F50).

**게이트 F** — 열린 질문 목록을 제시한다.
`[Phase 5] 열린 질문 {Q}개 · 결정 기록 {D}건 · 나만 아는 것 {S}건 — 마무리할까요?`

# 마무리

## 1. 산출물 저장 (opt-in)

저장 여부를 묻고, 동의 시 파일마다 **미리보기 → 승인 → 기록** 순으로 진행한다. 승인 없이 파일을 만들지 않는다. **커밋하지 않는다.**

## 2. 요약 보고

```
[Comprehension Loop] {대상} · 참여 목적 {X}
이해 항목: {N}개 (미확인 {U})
예측: {Q}문항 → 적중 {P}   게이트: 답한 것 {M}/{N}
지각–실제 격차: 확신 '높음'이었으나 틀린 항목 {G}건
모르는 채로 가는 것: {목록}          ← 반드시 명시
묻지 않은 범위: {목록}                ← 반드시 명시
마이크로월드: {만들지 않음(사유) | 생성(경로)}
열린 질문: {Q}개
```

> 게이트를 통과했다는 것은 **물어본 것에 답했다**는 뜻이지 이 변경을 이해했다는 뜻이 아니다(INV-4). 이 하네스가 정직하게 주장하는 것은 둘뿐이다 — **리뷰되지 않던 변경을 읽고 답한 변경으로 바꾼다**, **과확신을 낮추고 빈틈을 드러낸다**(INV-7).

## Common pitfalls

- **설명서를 먼저 보여준다** — 그 순간부터 측정되는 것은 이해가 아니라 기억이다(INV-3).
- **"이해했습니까? y/n"으로 게이트한다** — 자가평가는 센서가 아니다(INV-2).
- **통과/실패만 알려준다** — 틀린 사람에게 효과 0 구간이다(F18).
- **묻지 않은 것에 대해 안심시킨다** — 5문항은 5개 주장만 허가한다(F22).
- **점수·백분율·레벨을 만든다** — 검증된 계측 도구가 존재하지 않는다(INV-4).
- **결함을 찾기 시작한다** — 이 하네스는 판정하지 않는다. 열린 질문으로 적는다(INV-1).
- **마이크로월드를 기본으로 만든다** — 4조건 검사를 거치고, 스크러빙만 붙여놓고 참여했다고 보지 않는다(INV-5).
- **게이트를 거부권으로 쓴다** — 경고 후 사용자의 결정을 따른다(INV-6).
- **"이해도가 향상됩니다"라고 말한다** — 엔지니어의 코드 변경에 대해 측정된 적이 없다(INV-7).
- **질문을 한꺼번에 쏟아붓는다** — 한 번에 하나씩.
