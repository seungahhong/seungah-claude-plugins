# 이해 부채 지도 · 예측 커밋 (Phase 1)

목적 — **무엇을 모르는지의 목록**을 만들고, **설명을 보기 전에 예측을 받아낸다.**

> 순서가 규약이다. 설명을 먼저 읽히면 그 뒤에 무엇을 물어도 "설명을 기억하는가"만 측정된다. AI 설명은 이해를 검증하기 전에 **체감 이해를 유의하게 올리고**([evidence.md](./evidence.md) F8), 정오와 무관하게 수용률을 올린다(F9). 예측은 그 인플레가 일어나기 **전에** 받아야 한다.

---

## 1. 이해 범위는 "다음에 무엇을 할 것인가"가 정한다

**전부 이해하는 것을 목표로 삼지 않는다.** 퀴즈하지 않은 재료로의 전이는 신뢰할 수 없고(F22, d=0.16 n.s.), 5문항은 5개 주장만 허가한다.

Phase 0에서 받은 **참여 목적**(다음에 이 영역에서 무엇을 할 것인가)이 스코프를 정한다.

| 참여 목적 | 이해해야 하는 것 | 이해하지 않아도 되는 것 |
|---|---|---|
| 이 영역을 곧 다시 고칠 것이다 | 새 불변식·상태 전이·확장 지점·깨지는 조건 | 일회성 마이그레이션 스크립트 세부 |
| 이 위에 새 기능을 얹을 것이다 | 공개 계약·확장점·가정 | 내부 최적화 구현 |
| 사고가 나면 내가 대응한다 | 실패 모드·되돌리는 법·관측 지점 | 리팩터링된 이름 |
| 팀에 설명해야 한다 | 왜 이렇게 했는가·대안·트레이드오프 | 라인 단위 diff |
| 지금은 넘기고 나중에 본다 | **범위 밖임을 기록하고 종료** | — |

**스코프 밖은 "안 봤다"고 명시한다.** 조용한 절단은 금지다.

---

## 2. 이해 부채 표면 — 어디를 보는가

diff를 읽으며 아래 여섯 표면을 훑는다. 각 항목은 **관측**이지 결함 판정이 아니다.

| # | 표면 | 무엇을 찾는가 | 왜 부채인가 |
|---|---|---|---|
| **S1** | **새 개념** | 이 변경 전에 없던 명사 — 새 타입·상태·역할·좌표계·단위 | 이름은 있는데 머릿속 모형이 없는 상태 |
| **S2** | **새 불변식** | "항상 참이어야 하는 것" — 순서 의존·널 여부·범위·유일성·동시성 가정 | 어기면 깨지는데 어긴 줄도 모른다 |
| **S3** | **지시하지 않은 결정** | 내가 요구하지 않았는데 에이전트가 고른 것 — 라이브러리·자료구조·에러 처리 방침·기본값·추상 경계 | **부채의 최대 원천.** 요구에서 유도되지 않으므로 되짚을 근거가 없다 |
| **S4** | **멘탈모델 충돌** | 내가 알던 동작과 달라진 것 — 시그니처·반환 규약·부수효과·호출 순서 | 옛 모형으로 다음 변경을 짜면 틀린다 |
| **S5** | **경계 이동** | 책임이 옮겨간 곳 — 검증 위치·소유권·레이어 통과 | "여기서 처리되겠지"가 더 이상 참이 아니다 |
| **S6** | **되돌리기 어려움** | 스키마·저장 포맷·공개 시그니처·외부로 나간 것 | 모른 채 통과시키면 되돌릴 수 없다 |

**모르면 `미확인`으로 남기고 되묻는다.** 그럴듯하게 채우는 것이 이 Phase의 최악 실패다.

## 3. 항목마다 세 값을 적는다

```
[S3] 재시도 정책이 지수 백오프 + 최대 5회로 도입됨      ← 무엇이
왜 알아야 하나: 다음 스프린트에 같은 클라이언트를 큐 소비자로 재사용할 예정  ← 참여 근거
현재 상태: 추측  (앎 / 추측 / 모름)                      ← 자기 상태
```

- **참여 근거를 못 쓰는 항목은 스코프 밖이다.** "혹시 몰라서"는 근거가 아니다.
- **현재 상태는 게이트 조건이 아니다.** 자가평가 이해도의 판별력 상한은 우연 50% 대비 54.5%이고 실제 이해가 설명하는 분산은 R²≈5.9%다(F21). 이 값은 오직 **Phase 3에서 격차를 계산하는 한쪽 항**으로만 쓴다.

## 4. 예측 커밋 — 이 Phase의 산출물

각 이해 항목에서 **예측 문항**을 뽑는다. 사용자가 답을 제출하기 전에는 Phase 2의 설명서를 보여주지 않는다.

### 4.0 근거가 강제하는 네 가지 (2차 검증에서 확보)

| # | 규약 | 근거 |
|---|---|---|
| **P-a** | **답을 실제로 산출해 제출하게 한다.** "문항을 미리 보여준다"는 개입은 근거가 없다 | F65 — 산출 조건 **g=0.65** vs 문항만 읽힘 **g=0.22**(CI가 0을 포함), Q_B=11.05, p<.001. 이 문헌 전체에서 가장 강한 조절변인 |
| **P-b** | **공개는 예측 직후여야 한다.** 지연은 *읽기↔퀴즈* 구간이지 *예측↔공개* 구간이 아니다 | F67 — *"the correct answer has to be presented shortly after the guess."* |
| **P-c** | **확신 평정은 선택이 아니라 필수다.** "빨리 아무거나 찍어라"는 지지되지 않는다 | F68 — 메커니즘은 놀람이고 놀람의 크기는 **틀린 믿음에 대한 확신**의 함수다. 저확신 추측은 놀람을 만들지 못한다 |
| **P-d** | **예측↔공개 *불일치* 항목만 이해 주장의 대상이다** | F67 — 이득은 **기대 위반 항목에만** 있었고 기대 일치 항목은 n.s.(t(29)=−1.56, p=.13) |

**그리고 물어본 것 밖으로는 아무것도 이전되지 않는다** — 사전질문 일반 효과 **g=0.04 [−0.04, 0.11], k=91, p=.349**이고, 양의 방향으로 유의했던 셀조차 어느 것도 g=0.20을 넘지 않았다(F66). 이것은 F22와 **독립적인 두 번째 확증**이다.

> **예측(generation)과 설명 유도(elicited explanation)는 다른 개입이다**(F69: generation d=−0.15 / elicited explanation d=+0.36, Q(1)=33.20, p<.001). 이 Phase는 **예측(P-a)** 을 받는다. 설명 유도를 추가로 넣는다면 **같은 근거로 정당화하지 않는다.**

### 4.1 문항을 만드는 쪽은 에이전트다

사용자가 자기 문항을 만들게 하지 않는다 — 질문 *생성*의 효과는 +0.042, p=.406으로 **탐지되지 않는다**(F20). 답을 *생성*하는 것만 효과가 있다(+0.169 vs 읽기 −0.095).

### 4.2 무엇을 묻는가 — 메커니즘과 반증

| 물어야 하는 것 | 물으면 안 되는 것 | 근거 |
|---|---|---|
| "이 제어 흐름이 여기 **어떻게** 도달하나" | "이 변경이 왜 **옳은지** 설명하라" | 정당화 요구는 확증 추론을 부른다. 착각은 *메커니즘* 요구에서 드러난다(F29) |
| "**무엇이** 이걸 틀리게 만드나" | "이 함수가 무엇을 반환하나" | 반증 조건이 이해를 드러낸다 |
| "캐시가 비었을 때 **무엇이 깨지나**" | "이 변수 이름이 무엇인가" | 구문 문항은 측정 전략과 무관하게 가장 신뢰할 수 없다(F28) |
| "이 순서에 의존하는 **호출자는 누구인가**" | "몇 개 파일이 바뀌었나" | 나중에 실제로 산출해야 할 반응을 묻는다(F22 반응 일치성) |

### 4.3 형식

- **자유서술.** 객관식은 재인 조건이며 효과 대부분을 포기한다(F19: 재인 0.31 vs 단서회상 0.57).
- **답을 보기 전에 제출한다.** 제출 전에는 설명서·정답을 노출하지 않는다.
- **"모름"은 유효한 답이고 가장 유용한 답이다.** 모름을 벌하지 않는다 — 모름을 숨기는 것을 막는 게 목적이다.

### 4.4 확신 평정 — 필수 (두 가지 일을 한다)

각 예측 뒤에 확신을 받는다: `확신 [높음 / 보통 / 낮음]`. **생략할 수 없다.**

1. **메커니즘 조건** — 이 순서가 작동하는 메커니즘은 놀람이고, **놀람의 크기는 틀린 믿음에 대한 확신의 함수**다(F68). 확신 없이 받은 저확신 추측은 이 메커니즘 밖이다. 그래서 **"빨리 아무거나 찍으세요"라고 안내하지 않는다.**
2. **격차의 한쪽 항** — Phase 3에서 **지각–실제 격차**로만 보고한다. 재현 가능한 유일한 신호가 격차이기 때문이다(F48: 믿음 −20% vs 실제 +19%; F49: 안전하다는 믿음 vs 비안전 코드).

**이 값은 점수가 아니다.**

### 4.5 개수

**근거는 개수를 정하지 않는다.** 강연의 "5문항"은 1차 출처가 없다([evidence.md](./evidence.md) §10). 근거가 강제하는 것은 개수가 아니라 **초기 성공률 >50%, 이상적으로 >75%**다(F18).

운영 지침: **이해 항목당 예측 1개, 최대 7개.** 7개를 넘으면 스코프가 넓다는 신호이므로 참여 목적으로 다시 좁힌다.

## 5. 게이트 무게 — diff 크기가 아니라 자동화 경계로

부정적 결과는 자동화가 *정보 분석*에서 *행동 선택*으로 넘어가는 지점에 집중된다(F51).

| 변경의 성격 | 게이트 무게 |
|---|---|
| 에이전트가 **분석·설명만** 했고 사람이 변경을 골랐다 | 가벼움 — 예측 2~3개 |
| 에이전트가 **변경을 골라 적용**했다 | 무거움 — 예측 5~7개 + 교정 피드백 필수 |
| 에이전트가 골라 적용했고 **되돌리기 어려운 표면(S6)** 을 건드렸다 | 최대 — 위 + 지연 재발화 제안 |

**두 번째 티어링 축 — 리뷰어의 해당 서브시스템 사전지식.** 세 문헌이 독립적으로 같은 결론에 닿는다: 고 사전지식에서는 강한 유도가 동등하거나 해롭다(F69 Kirschner 범위 한정 · F15 전문성 역전 · F64 EI 라우팅 가설). **잘 아는 코드에 무거운 게이트를 거는 것은 이 문헌들이 지지하지 않는다.** Phase 0 #3의 답으로 게이트 무게를 한 단계 낮춘다(①처음 → 유지 / ②익숙 → 한 단계 낮춤 / ③내가 설계했다 → 두 단계 낮춤).

**마찰을 균일하게 깔지 않는다.** 과의존을 가장 많이 줄인 설계가 가장 낮은 선호 평가를 받았고 전체 과의존 감소는 비유의였다(F13). 저자 권고대로 **적응적으로, 소수 사례에만** 강하게 건다.

**대비해야 할 실패는 "미움받는 것"이 아니라 "형식적 통과"다.** 예측 개입의 *즐거움*은 오히려 높을 수 있고, 낮은 것은 **효능에 대한 믿음**이다 — 학습자는 사전질문을 최하 순위로 평가하고 **78%가 읽기를 더 효과적이라고 답한다**(F70). 그래서 하네스는 "이거 왜 하냐"에 답할 준비를 하되, **의미 없다고 믿으면서 아무 답이나 적어 통과시키는 것**을 실제 실패 모드로 본다(P-c의 확신 평정이 이 신호를 잡는다).

## 6. 동시 처리 한도

한 사람이 여러 에이전트 산출물을 동시에 감독하는 상황은 **안주 조건을 제조하는 것**이다 — 안주는 다중 과제 부하에서만 나타나며, 자동화 편향은 훈련·지시로 예방되지 않는다(F52).

이것은 관측할 수 없으므로 **묻지 않고 카드에 `미확인`으로 둔다.** 사용자가 스스로 여럿이라고 말하면 그때 **한 번에 하나씩** 돌리자고 제안한다. "집중해서 보세요"라는 훈계로 대체하지 않는다 — 이 근거가 직접 부정하는 처방이다.

## 6-bis. 인테이크 마찰 예산 — 두 번만 묻는다

인테이크에서 묻는 것은 **대상 변경**과 **참여 목적** 둘뿐이다. 사전지식·에이전트 역할·산출물 위치·동시 대기·시간 예산은 **관측하거나 잠정값으로 적고 게이트 A에서 한 번에 정정받는다.**

왜 절제가 규약인가 — 마찰의 실패 모드는 "싫어함"이 아니라 **"의미 없는 절차라고 믿으면서 형식적으로 통과시키는 것"** 이다(F70: 예측 과제의 즐거움은 오히려 높고, 낮은 것은 효능에 대한 믿음이며, 78%가 읽기를 더 효과적이라고 답한다). 인테이크에서 일곱 번 묻고 시작하면 정작 마찰이 필요한 지점(예측 커밋, §4)에 도달했을 때 이미 아무 답이나 적는 상태가 된다. **마찰 예산은 예측 커밋에 쓴다** — 강한 게이트는 적응적으로 소수 사례에만 건다는 것이 이 문헌의 권고다(F13).

같은 이유로, 사용자가 **한 산출물을 지목**해 들어왔으면(설명서만·시뮬레이터만·퀴즈만) 전체 루프를 말없이 시작하지 않고 **단축 경로를 제시**한다. 다만 **예측 커밋만은 어느 경로에서도 유지한다** — 그것을 빼면 이 하네스는 문서 생성기가 되고, 축약한 경우 산출물에 **"이해를 실측하지 않았다"** 를 적는다.

## 7. 안티패턴

- **설명을 먼저 보여주고 예측을 받는다** — 그 시점부터 측정되는 것은 이해가 아니라 기억이다(F8·F9).
- **"이해했습니까? y/n"으로 게이트한다** — 자가평가는 센서가 아니다(F21).
- **참여 근거 없이 항목을 늘린다** — 스코프가 넓어지면 전이가 붕괴한다(F22).
- **모르는 축을 그럴듯하게 채운다** — `미확인` + 되물음이 정답이다.
- **결함을 찾기 시작한다** — 이 하네스는 판정하지 않는다. 이상한 점은 **열린 질문**으로 적고 넘긴다.
- **저자가 사람인지 에이전트인지로 강도를 정한다** — 강도는 **자동화 경계**로 정한다(F51).
