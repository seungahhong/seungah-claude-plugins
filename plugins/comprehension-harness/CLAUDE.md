# comprehension-harness

에이전트가 쓴 코드 변경을 **사람이 실제로 이해하고 있는지 실측하고 그 이해를 자산으로 남기는** 도메인 무관 인터랙티브 멀티 에이전트 하네스. 한 문장 원칙은 **"이해했다는 느낌은 이해의 증거가 아니다"** 이며, **검증을 위한 이해가 아니라 참여를 위한 이해**를 만든다. 이해 부채를 6표면으로 지도화하고 **설명서 공개 전에 예측을 받아낸 뒤**(Phase 1), 검증 훅이 붙은 설명서를 **예측 채점과 함께** 공개하고(Phase 2), 자유서술 회상 + 교정 피드백으로 실측하며 **묻지 않은 범위를 열거**하고(Phase 3), 조건 충족 시에만 일회용 마이크로월드를 만들고(Phase 4), 팀에서 **나만 아는 것을 뽑아낸다**(Phase 5). **결함을 판정하지 않고 코드를 고치지 않으며 점수를 만들지 않는다.**

사용자용 개요·사용법은 [README.md](README.md), 근거 정본은 [skills/comprehension-loop/references/evidence.md](skills/comprehension-loop/references/evidence.md) 참조.

## 6 Phase 요약

| Phase | 에이전트 | 산출 | 게이트 |
|-------|----------|------|--------|
| 0 이해 인테이크 | (오케스트레이터) | 대상·**참여 목적**·사전지식·에이전트 역할·예산·동시대기 — **한 번에 한 질문** | A |
| 1 이해 부채 지도 | `debt-cartographer` | 6표면(S1~S6) + 스코프/스코프 밖 + **예측 문항 + 확신 평정** | B |
| 2 설명서 공개 | `explainer-architect` | 5블록(**검증 훅 중심**) + `[확인]`/`[추론]` 비율 + **예측 채점 동시 공개** | C |
| 3 이해 검증 게이트 | `comprehension-examiner` | 자유서술 회상 + **교정 피드백(diff 좌표)** + 지각–실제 격차 + **묻지 않은 범위** | D |
| 4 마이크로월드 *(조건부)* | `microworld-builder` | **만들지 않음(사유)** 또는 조건 충족 자체완결 HTML(예측 커밋 포함) | E |
| 5 공유 이해 *(조건부)* | `shared-context-curator` | 열린 질문 + 결정 기록 + 나만 아는 것 + 공용 이름 | F |

## Conventions (핵심 불변식)

- **INV-1 검증이 아니라 참여를 위한 이해(최강 불변식)** — **결함·리스크·머지 가능 여부를 판정하지 않는다.** 이상한 점은 `열린 질문`으로 적고 넘긴다. **코드를 수정하지 않고** `git commit`/`git push`/PR 생성·승인·머지를 **하지 않는다.** 산출물은 이해 자산이다.
- **INV-2 자기보고는 센서가 아니다** — "이해했습니까? [y/n]"을 게이트 조건으로도 지표로도 쓰지 않는다(자가평가 판별력 상한 54.5%·R²≈5.9%). 확신 평정은 **오직 지각–실제 격차의 한쪽 항**으로만.
- **INV-3 설명은 예측 뒤에 공개된다** — AI가 쓴 설명은 이해 도구이기 전에 **과확신 장치**다. ⓐ 사람이 **답을 산출해 제출한 뒤에만** 공개(문항을 보여주기만 하는 것으론 부족: 산출 g=0.65 vs 읽힘 g=0.22) ⓑ **예측 직후에** 공개(지연은 *읽기↔퀴즈* 구간이지 *예측↔공개* 구간이 아님) ⓒ 대조 불가능한 것을 단언하지 않음(`[확인]`/`[추론]` 분리) ⓓ **그 자체로는 어떤 게이트도 통과시키지 못함.** 이득은 **예측이 빗나간 항목에만** 있으므로 불일치를 앞에 놓는다. **이것이 강연 원안과 가장 크게 갈라지는 지점이다.** 단 이 순서가 사는 결과변수는 *물어본 항목의 학습*이며 캘리브레이션 개선은 **미측정 도약**이다.
- **INV-4 퀴즈 통과는 이해의 증명이 아니다** — 통과 = "물어본 것에 답했다". **점수·백분율·성숙도 등급 금지**(검증된 코드 이해 계측 도구가 존재하지 않는다). **묻지 않은 범위를 반드시 열거**한다. **게이트 판정에 쓸 수 있는 것은 A형(적혀 있는 것의 회상)뿐**이고 B형(구조 도출)은 `[빈틈 노출 전용]`, C형은 적용 능력의 증거가 아니다.
- **INV-5 마이크로월드는 기본값이 아니라 명시된 가설** — 우리 도메인은 미측정이고 **인접한 네 하위군 전부에서 메타분석 추정치가 0 또는 음수**(추상 표상 g=0.006 n.s. · 정보학 g=0.108 n.s. · 완전 학습자 통제 **−0.120** · 이해/전이 결과변수 최소). opt-in · 값싼 대안 먼저 · 조건 **관측·고지**(스크러빙은 "근거 없음"이 아니라 **점추정이 음수인 구간**, 구조·배치는 정적 1장이 이김 d=1.30, 사전지식은 조건 아님) · 폐기 전제 · 제품 코드에 안 섞음 · 사용 기록. **단 조건은 게이트가 아니라 권고다** — 전이되지 않는다고 스스로 적어 둔 근거로 사용자의 명시 요청을 기각하지 않는다(INV-6와 같은 규칙).
- **INV-6 게이트는 경고이지 거부권이 아니다** — 못 맞혀도 사용자가 진행을 선택하면 **따르고**, **무엇을 모르는 채로 가는지** 한 줄로 알린다. 승인된 진행을 조용히 보류하지 않는다.
- **INV-7 효과를 약속하지 않는다** — 주장 가능한 것은 둘뿐(리뷰되지 않던 변경을 읽고 답한 변경으로 / 과확신을 낮추고 빈틈을 드러냄). **"이해를 보장한다"·"다음 아이디어를 빠르게 한다"·"결함 N% 감소"·"이해도 N% 향상" 금지.**
- **쓰는 역할과 캐묻는 역할을 분리한다** — `explainer-architect`(2)와 `comprehension-examiner`(3)는 다른 에이전트다. 같은 에이전트가 자기 설명서를 근거로 문항을 내면 **문항이 설명서의 요약이 되고 측정 대상이 이해에서 "그 문서를 읽었는지"로 바뀐다.** `comprehension-examiner`의 문항 근거는 설명서가 아니라 **diff**다.
- **한 번에 한 질문 · 매 Phase 승인 게이트 · opt-in 저장 · 커밋 안 함**.
- **근거는 evidence.md가 정본** — 등급(`[PRIMARY-STRONG]`/`[PRIMARY-COND]`/`[SECONDARY]`/`[INDUSTRY]`/`[관행]`/`[REFUTED]`) 없는 사실 주장은 결함이다. **인용 금지 목록**은 어떤 산출물에서도 사실로 말하지 않는다. 하네스가 인용하는 정량치는 **엔지니어의 코드 변경에 대해 측정된 적이 없다는 사실을 본문에 적는다.**
- **경계** — 결함 판정·머지 결정, 착수 *전* 상류 산출물 게이트, 명세 기반 구현·검증, 테스트 신규 계획·생성, 저장소 전체 정적 측정, 사람↔에이전트 분업·감독 체계 설계, 프로덕션 장애 대응, 하네스 자체 진단은 범위 밖. 경계는 **범주로만** 서술하고 다른 플러그인을 이름으로 참조하지 않는다(독립 플러그인·references 6종 내재화).
- 5개 에이전트가 협업하는 하네스이므로 `agents/{name}.md`를 두고 SKILL.md의 **모든 Agent 호출에 `model: "opus"`를 명시**한다.
