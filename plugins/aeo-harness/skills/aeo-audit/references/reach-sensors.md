# 도달 센서 (Phase 1)

**질문: 에이전트가 이 문서에 도달해서 몇 번의 왕복으로 필요한 것을 얻는가.**

이 레인의 산출물은 전부 **도달·효율** 언어로만 쓴다. 정확도·품질·성숙도 단어를 쓰지 않는다(INV-1). 근거 ID는 [`evidence.md`](./evidence.md)를 가리킨다.

결정론 프로빙은 [`../scripts/reach_probe.py`](../scripts/reach_probe.py)로 수행한다(stdlib만 사용, 네트워크 접근은 사용자 승인 후).

---

## R1 — 링크 지도가 있는가 (1급 센서)

**왜 1급인가.** 관측된 실패는 "마크다운을 안 줘서"가 아니라 **"어떤 페이지가 존재하는지 알려주지 않아서"** 였다. 마크다운으로 서빙하되 내비게이션을 벗겨 내자 에이전트가 `.md` 경로를 스스로 지어내 **HTML일 때보다 더 많이 틀렸다**(F23: "Plain markdown was arguably the worst of the four formats ... guessed more wrong URLs than they had on HTML"). 지도를 주자 태스크당 404가 2.23 → 0.11로 떨어졌다.

**무엇을 센다** (형태는 무관, 아래 중 하나라도 있으면 "지도 있음"):
- 사이트맵(`sitemap.xml`)이 문서 경로를 포함하는가
- 문서 진입점(예: `/docs`)에서 **한 번의 페치로** 나머지 페이지 링크가 노출되는가
- `llms.txt`처럼 링크 목록을 담은 파일이 있는가 — **파일명이 아니라 "링크 목록이 한 번에 손에 들어오는가"가 판정 기준이다**
- 마크다운 변환본에도 내비게이션 링크가 살아 있는가 (Cloudflare 변환은 비콘텐츠 요소를 제거한다, F25)

**보고 형식**
```
R1 링크 지도: 있음 / 없음 / 부분(HTML에만 있고 .md 변환본에서 소실)
  근거: <어느 URL을 한 번 페치해 링크 N개를 얻었는가>
```

**금지** — "llms.txt가 없으므로 AI 가시성이 낮다"(인용 금지 #3). 이 센서가 재는 것은 **왕복 낭비**이지 노출이 아니다.

## R2 — 본문이 JS 없이 초기 HTML에 있는가

측정된 코딩 에이전트 9종 중 헤드리스 브라우저를 쓰는 것은 2종뿐이고 나머지는 경량 HTTP 클라이언트다(F19). 클라이언트 렌더링 문서는 그 7종에게 본문이 비어 보인다.

**절차**
1. JS를 실행하지 않는 단순 GET으로 페이지를 가져온다.
2. 본문 텍스트 길이·헤딩 수·코드블록 수를 센다.
3. 같은 페이지를 사람이 보는 상태(렌더링 후)와 비교할 수 있으면 비교하고, 없으면 **"렌더링 후 비교 미수행"으로 표기**한다.

**판정**: 초기 HTML에 본문 텍스트가 사실상 없으면(예: 코드블록 0 + 텍스트 극소) `CSR 의존 의심`으로 보고한다. **단정하지 않는다** — 단일 페이지 관측이다.

## R3 — `.md` 접미사 / `Accept: text/markdown` 협상

**관행이 표준화되어 있지 않다**(F26). 접미사만 지원(VitePress·react.dev·Stripe·Vercel), 헤더만(GitHub Docs), 둘 다(Mintlify·GitBook·Cloudflare 계열), **둘 다 없음(Docusaurus·Nextra·Starlight 기본값)** 으로 갈린다. 게다가 **`.md`가 `text/markdown` MIME을 보장하지 않는다** — react.dev·Stripe는 `text/plain`으로 준다.

**절차**: 같은 페이지에 대해 ① 평범한 GET ② `Accept: text/markdown` ③ URL + `.md` 세 가지를 각각 요청해 상태코드·`content-type`·`vary` 헤더를 기록한다.

**보고**
```
R3 마크다운 제공: 접미사 <200 text/markdown | 404 | 200 text/plain> / 헤더 <...> / vary <...>
```

**토큰 절감률을 남의 수치로 옮기지 않는다**(인용 금지 #7). Cloudflare 뒤라면 응답의 `x-original-tokens`·`x-markdown-tokens`로 **자기 페이지에서 직접** 재고, **베이스라인이 무엇인지**(원시 HTML 통째 대비인지) 함께 적는다(F25).

## R4 — 죽은 링크·앵커·soft-404·리다이렉트 체인

404는 에이전트 왕복의 직접 낭비다(F23). 이 센서는 인과가 자명하고 검사가 결정론이라 **Tier A 개입의 근거**가 된다.

**센다**: 문서 내부 링크의 상태코드 / `#fragment`가 실제로 존재하는지 / 200을 반환하지만 본문이 "찾을 수 없음"인 soft-404 / 교차 호스트 리다이렉트 체인 길이.

**주의**: 링크 전수 페치는 대상 사이트에 부하를 준다. **사용자 승인 후에만** 돌리고, 동시성·요청 간격을 보수적으로 잡으며, 표본만 돌렸으면 그 사실을 적는다.

## R5 — 벤더 UA·IP replay로 오차단 탐지

**403이면 콘텐츠가 0**이라는 인과는 정의상 확정적이다. 이 센서는 "차단당하고 있는가"를 재는 것이지 "누가 왔는가"를 재는 것이 아니다.

**절차**: 벤더가 **공식 문서에 게시한 전체 UA 문자열**로 문서 URL을 요청해 상태코드를 평범한 브라우저 UA 응답과 비교한다. 200이 아니면 오차단 후보로 보고한다.

**보고 가능한 UA 문자열의 출처**(전부 벤더 공식 문서, F30):
- OpenAI — `GPTBot/1.4`(학습) · `OAI-SearchBot/1.4`(검색 색인) · `ChatGPT-User/1.0`(사용자 트리거) · `OAI-AdsBot/1.0`, 전체 문자열 게시
- Perplexity — `PerplexityBot/1.0`(검색 색인, 학습 아님 명시) · `Perplexity-User/1.0`(사용자 트리거), 전체 문자열 게시
- Google — 사용자 트리거 fetcher 다수(`Google-Agent`·`Google-GeminiNotebook`·`Google-Read-Aloud` 등), 전체 문자열 게시
- Anthropic — `ClaudeBot`(학습) · `Claude-User`(사용자 트리거) · `Claude-SearchBot`(검색), **토큰만 제공하고 전체 UA 문자열은 미게시**

**INV-5 준수**: 이 센서의 결과는 **"이 UA로 요청하면 200이 나오는가"** 이지 "누가 왔는가"가 아니다. 로그 분석에서 UA로 도구를 귀속하지 않는다 — `curl/8.4.0`을 Cline과 Junie가 공유하고(F19), 값이 릴리스마다 바뀌며(F19), Google은 위조 가능을 명시한다(F29).

**진위 판정이 필요하면 IP·rDNS로만** 한다(F30):
- IP 목록 JSON: OpenAI 봇별 4개 · Perplexity 봇별 2개 · Google 소유주체별 3개 · **Anthropic 단일 통합**(봇별 분리 불가 → "Anthropic에서 왔다"까지만 증명)
- rDNS 2단계 검증 절차를 제공하는 것은 **Google뿐**
- Perplexity는 벤더 자신이 **UA 매칭 + IP 검증 AND 결합**을 권고한다(F31)

## R6 — `robots.txt` 파싱 결과 보고 (편집 금지)

**이 센서는 report-only다**(INV-4). 학습 옵트아웃과 검색 노출이 얽힌 정책 결정이며 단일 정답이 없다.

**보고할 것**: 문서 경로(`/docs` 등)에 걸린 `Disallow` / 문서 서브도메인의 별도 `robots.txt` 유무 / 스테이징에서 넘어온 `Disallow: /` 잔존 / 벤더별 UA 규칙.

**함께 반드시 적을 사실**(F18·F28):
- 측정된 **코딩 에이전트 9종은 `robots.txt`를 요청조차 하지 않았다.** `robots.txt`를 읽은 2종은 어시스턴트 웹서비스(Claude·MistralAI)이고 **Claude Code는 포함되지 않는다.**
- 사용자 트리거 페치의 취급이 벤더마다 다르다 — Google·Perplexity는 "generally ignores"(단정), OpenAI는 "may not apply"(약한 표현), **Anthropic은 면제 문장 없이 포괄 준수를 선언**한다.
- 따라서 **"robots.txt 오설정이 에이전트를 조용히 차단한다"고 쓰지 않는다**(인용 금지 #5). 실제 차단은 자발적 준수 계층이 아니라 **WAF/IP 계층**에서 일어난다.
- "벤더가 준수를 **선언**했다"와 "준수**한다**"를 구분해 쓴다. 후자는 3자 측정이 없어 UNVERIFIED다.

## R7 — 페이지 토큰량 census

**임계값도 등급도 만들지 않는다.** 널리 인용되는 상한 수치(15,000 / 25,000 / 20,000)와 "100K~200K 실사용 한도"는 **1차 출처에 존재하지 않는다**(인용 금지 #1·#2). 인용된 논문은 오히려 "이 연구는 토큰 소비나 문서 크기를 측정하지 않았다"고 적는다(F20).

**보고**: 페이지별 추정 토큰량의 **분포**(중앙값·상위 10개)와, 한 페이지를 통째로 넣었을 때의 규모감. 그 이상 해석하지 않는다.

상한을 정하고 싶다는 요청에는 이렇게 답한다 — **"문헌 근거가 없으니, 우리 태스크 배터리(Phase 4)로 재서 우리 기준을 만들자."** 그리고 그 기준에는 **"우리 환경에서 측정해 정한 운영 기준이며 문헌 근거는 없다"**를 표기한다.

## R8 — 머신 리더블 스펙 존재

OpenAPI / GraphQL SDL / `.proto` / `.d.ts` / Sphinx `objects.inv` 등이 **존재하고 유효하게 파싱되는가**만 본다.

**정직성**: 스펙 제공이 코드 정확도를 올린다는 **측정은 확인되지 않았다.** 관측된 것은 일부 에이전트가 OpenAPI/Swagger 경로를 훑는다는 행동뿐이다(F18의 Cline pre-fetch). 따라서 이 항목은 **존재 보고**이고, 개입은 T-B(추가 시 파싱 검증 필수)로 다룬다.

## 못 잰 것을 반드시 열거한다

서버측 관측은 **원리적으로 불완전**하다(F27):
- 캐시된 크롤 색인에서 읽는 도구는 사이트를 **방문조차 하지 않아** 어떤 로그에도 남지 않는다.
- 코딩 에이전트 7종 중 표준 접근 로그로 식별 가능한 것은 3종이고, 2종은 서버측 탐지가 사실상 불가하다.
- MCP 도구·로컬 파일·설치된 패키지로 문서가 전달되는 경로는 이 레인 전체가 무의미해진다 — Phase 0에서 경로를 물은 이유다.

**보고 말미에 "이 조사가 보지 못한 경로"를 목록으로 남긴다.**
