# 개입 티어 (Phase 3)

개입은 **근거의 강도가 아니라 되돌리기 비용과 판정 가능성**으로 나눈다. 근거 ID는 [`evidence.md`](./evidence.md).

| 티어 | 판정 기준 | 적용 방식 |
|---|---|---|
| **T-A 위험 0** | 파싱·실행으로 **거짓이 판정된** 것을 제거·수정 | 계획 승인 + **항목별 개별 승인** 후 적용 |
| **T-B 검증 가능** | 추가·보강하되 **적용 후 결정론 검증을 통과해야** 반영 | 검증 실패 시 되돌린다 |
| **T-C report-only** | 근거가 약하거나 정책 결정이거나 효과가 미측정 | **만들지도 고치지도 않는다.** 사용자에게 넘긴다 |

---

## T-A 위험 0 — 거짓 제거

**포함**
- C4에서 거짓으로 판정된 서술(존재하지 않는 파라미터·삭제된 심볼·틀린 타입/스키마)
- 임포트가 실패하는 예제의 수정
- 죽은 링크·존재하지 않는 앵커·soft-404 대상 링크(R4)
- 사내 문서라면 C6에서 발견된 주입 표면 제거

**왜 위험 0인가.** 틀린 문서가 없는 문서보다 나쁘다는 것은 확인된 방향이고(F8), 여기 올라오는 항목은 **거짓임이 기계로 판정된 것**뿐이다. 삭제·교정이 새 정보를 만들지 않으므로 새 오류를 들여올 여지가 작다.

**그래도 개별 승인을 받는다.** 문서는 조직의 산출물이고, "존재하지 않는 파라미터"가 실은 **아직 배포되지 않은 기능**일 수 있다. 각 항목에 **어떻게 거짓으로 판정했는지**(어떤 명령·어떤 출력)를 붙인다.

---

## T-B 검증 가능 — 추가·보강

**포함**
- C1 공백 심볼에 **예제 추가**
- R1 링크 지도 보강(진입점에서 링크가 한 번에 잡히게)
- R8 머신 리더블 스펙 노출·수정

**필수 규칙 — 생성물은 검증을 통과한 것만 반영한다.**
**검증 없이 LLM이 문서를 새로 쓰는 것은 순마이너스로 취급한다**(INV-2). 근거는 두 갈래다: 틀린 문서의 해악이 확인됐고(F8), 예제의 효과는 그것이 **실제로 동작할 때** 이야기다(F2의 ablation은 동작하는 예제를 뺐을 때의 낙폭이다).

- 추가한 예제는 **반드시 C2(컴파일·실행)를 통과**해야 한다. 통과하지 못하면 반영하지 않는다.
- 추가한 링크는 **R4(상태코드·앵커)를 통과**해야 한다.
- 추가한 스펙은 **스키마 검증을 통과**해야 한다.

**우선순위**: C5에서 **낯선 심볼**로 판정된 것부터. 잘 알려진 심볼은 검색 품질이 확보된 경우에만 손댄다(F3). 단 "고빈도 API는 문서가 쓸모없다"는 뜻이 아니다(F2 RQ4).

## T-C report-only — 만들지도 고치지도 않는다

각 항목은 **무엇을 · 왜 · 근거 등급 · 트레이드오프 · 못 하는 팀의 대체 경로**를 적어 사용자에게 넘긴다. 하네스는 실행하지 않는다(INV-4).

**단 거부권은 아니다** — 사용자가 근거의 약함을 알고도 하겠다고 하면 따르고, 무엇을 모르는 채 하는지 한 줄 남긴다.

### T-C-1 `llms.txt` 생성

**정직한 목적 서술**: *"AI 노출·인용을 올리기 위해서"가 아니라, "문서를 페치하는 코딩 에이전트에게 **링크 지도**를 주기 위해서"* 다.

| 항목 | 사실 |
|---|---|
| 표준인가 | **아니다.** 명세 원문이 "A proposal to standardise..."이고, 파일을 **어떻게 소비할지에 대한 권고를 담지 않는다** |
| 소비 증거 | 통제 실험에서 **15개 도구 중 0개가 요청**(F18, 단 URL이 직접 주어진 조건) / 서버 로그에서 **보유 도메인의 97%가 한 달간 요청 0**(F22) |
| 반대 증거 | docs를 지목받은 코딩 에이전트는 `/llms.txt`를 **요청해서 404를 냈다**(F23) → "절대 안 찾는다"는 전칭 주장도 성립하지 않는다(F24) |
| 재현된 이득 | **정확도가 아니라 효율** — 404/태스크 2.23→0.11, "The win was efficiency, not correctness"(F23, 벤더 자체측정) |
| Google | Search 문서는 llms.txt를 **언급조차 하지 않고**(F32), Lighthouse는 **부재를 감점하지 않는다**(404 → N/A, F34) |
| 크기 규정 | 명세에 **토큰·바이트 상한이 없다**. "5,000 토큰 이하" 류는 2차 관행이다 |

**대안**: 이 파일을 만들지 않아도 R1을 충족할 수 있다 — 사이트맵이 문서를 포함하거나, 진입점 한 번에 링크가 잡히면 된다. **판정 기준은 파일명이 아니라 "링크 목록이 한 번에 손에 들어오는가"** 다.

### T-C-2 `robots.txt` 편집

**정책 결정이라 단일 정답이 없다.** 학습 옵트아웃과 검색 노출이 얽혀 있다.

- 측정된 **코딩 에이전트 9종은 `robots.txt`를 요청조차 하지 않았다**(F18). 읽은 2종은 어시스턴트 웹서비스이고 Claude Code는 아니다.
- 사용자 트리거 페치 취급이 벤더마다 다르다 — Google·Perplexity "generally ignores"(단정), OpenAI "may not apply", **Anthropic은 면제 없이 포괄 준수 선언**(F28).
- **"오설정이 에이전트를 조용히 차단한다"고 쓰지 않는다**(인용 금지 #5). 실제 차단은 WAF/IP 계층에서 일어난다 → 그쪽은 R5로 관측한다.
- "벤더가 준수를 **선언**했다"와 "준수**한다**"를 구분한다. 후자는 3자 측정이 없어 UNVERIFIED다.

### T-C-3 마크다운 전환·콘텐츠 협상 도입

**반드시 함께 적을 위험**: **내비게이션이 함께 제거되면 역효과다.** 마크다운으로 서빙하되 내비를 벗겨 낸 사례에서 에이전트가 경로를 지어내 **HTML보다 더 많이 틀렸다**(F23). 엣지 변환 역시 비콘텐츠 요소(헤더·푸터·내비게이션)를 제거한다(F25).

| 항목 | 사실 |
|---|---|
| 메커니즘 | `Accept: text/markdown` 콘텐츠 협상(엣지 실시간 변환) 또는 `.md` 접미사 — **관행이 표준화되어 있지 않다**(F26) |
| 제약 | 존 단위 **옵트인**, **Pro 이상 플랜**(Free 제외), HTML만, 오리진 응답 **2MB 상한**, **`ETag`·`Last-Modified` 제거**(조건부 요청·캐시 재검증 포기) (F25) |
| MIME | `.md`가 `text/markdown`을 보장하지 않는다(react.dev·Stripe는 `text/plain`) (F26) |
| 절감률 | **공식 문서에 수치가 없다.** 남의 수치를 옮기지 말고 `x-original-tokens`·`x-markdown-tokens`로 **자기 페이지에서 직접** 재고 **베이스라인 정의**를 함께 적는다(인용 금지 #7) |
| 못 쓰는 팀 | 플랫폼이 지원하지 않으면(Docusaurus·Nextra·Starlight 기본값) **해당없음**으로 판정한다. 미통과가 아니다 |

### T-C-4 문서 구조·서식 재편

헤딩 깊이·목차·섹션 순서·표 대 산문의 효과를 **분리 측정한 연구를 찾지 못했다**(evidence UNVERIFIED). 청킹 근거는 **문서가 아니라 소스 코드** 대상이고(F17), 의미 단위 분할이 자동으로 우월하지도 않았다.

→ **제안조차 신중히**, 자동 수정 금지. 토큰 상한을 정하고 싶다면 Phase 4로 재서 **"우리 환경 기준이며 문헌 근거 없음"**을 표기한다.

### T-C-5 컨텍스트 파일(`AGENTS.md`·`CLAUDE.md`) 작성

**이 하네스는 만들지 않는다.** 근거가 출처별로 갈리고 서로 반박한다 — LLM 생성본은 생략 권고이고 developer-provided는 +2.4%(p=0.21)였으며(F11), 반대 방향 연구도 있다(F13). 게다가 두 연구를 같은 방향으로 병렬 인용할 수 없다.

### T-C-6 `agent-permissions.json`

**표준이 아니라 측정 없는 제안서**이고, 저자가 **`non-enforceable by design`**을 명시한다(F21). 신뢰 경계 강제의 근거로 쓸 수 없다. 언급 수준으로만 넘긴다.

```
  ...
[T-B] 2건 — 적용 후 검증 통과해야 반영
  1. `Client.stream()` 예제 추가 (C1 공백, C5 낯선 심볼)
     검증: 추가 예제 실행 → 통과해야 반영
[T-C] 4건 — 사용자에게 넘김 (하네스가 실행하지 않음)
  1. llms.txt 생성 — 목적: 링크 지도. 근거: 효율 개선은 벤더 자체측정, 소비 증거는 갈림
     대안: sitemap이 docs를 포함하면 R1 충족
```
