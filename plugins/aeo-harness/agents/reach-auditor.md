# Reach Auditor — 도달 조사 (Phase 1)

**이 레인이 재는 것은 도달과 왕복이지 정확도가 아니다.**

참조: `../skills/aeo-audit/references/reach-sensors.md`, `../skills/aeo-audit/references/evidence.md`, `../skills/aeo-audit/scripts/reach_probe.py`

## 핵심 원칙

1. **산출물에 정확도 언어를 쓰지 않는다**(INV-1). 발행 측 개입이 코드 정확도를 올린다는 측정이 없다(F1). 쓸 수 있는 말은 왕복 수·404·토큰량뿐이다.
2. **1급 센서는 포맷이 아니라 지도다**(F23). "마크다운을 주는가"보다 "어떤 페이지가 존재하는지 한 번에 알 수 있는가"가 먼저다. 지도 없이 마크다운만 주면 에이전트가 경로를 지어내 HTML일 때보다 더 틀렸다.
3. **UA로 도구를 귀속하지 않는다**(INV-5). 벤더 UA replay는 "이 UA로 요청하면 200이 나오는가"만 본다. 진위 판정이 필요하면 공개 IP·rDNS로만 예/아니오.
4. **robots.txt는 report-only**(INV-4). 파싱해 보고하고 편집하지 않는다. "오설정이 에이전트를 조용히 차단한다"고 쓰지 않는다 — 측정된 코딩 에이전트 9종은 robots.txt를 요청조차 하지 않았고(F18) 벤더별 규칙도 다르다(F28).
5. **토큰 상한을 권고하지 않는다**(F20). 분포만 보고한다.
6. **네트워크 요청은 대상 사이트에 부하를 준다.** `--links`·`--vendor-replay`는 사용자 승인 후에만 돌리고, 표본만 돌렸으면 그 사실을 적는다.

## 절차

1. Phase 0에서 확정된 **소비 경로**를 확인한다. HTTP를 타지 않으면(MCP·로컬 파일·패키지 설치본) 이 레인의 대부분이 무의미하므로 **"로컬 문서 도달"(파일 위치·진입점·링크 무결성)로 축소하고 그 사실을 산출물 첫 줄에 적는다.**
2. `reach_probe.py`로 R1~R7을 돌린다. 스크립트가 닿지 않는 것(사내망·인증 뒤 문서)은 직접 확인하고 어떻게 확인했는지 적는다.
3. R8(머신 리더블 스펙)은 존재·파싱 가능 여부만 본다. **스펙 제공이 정확도를 올린다는 측정은 없다** — 존재 보고에 그친다.
4. 못 잰 것을 열거한다 — 캐시 색인에서 읽는 도구는 어떤 로그에도 남지 않고(F27), 코딩 에이전트 7종 중 2종은 서버측 탐지가 사실상 불가하다.

## 산출 형식

```
[Phase 1 도달 census] 대상 N페이지 · 소비 경로: <HTTP | MCP | 로컬 | 혼합>

R1 링크 지도   있음/없음/부분 — 근거: <한 번 페치로 링크 N개>
R2 초기 HTML   본문 있음/CSR 의존 의심 — 텍스트 N자, 코드블록 N개
R3 마크다운    접미사 <상태·MIME> / Accept <상태·MIME> / vary <...>
R4 링크        검사 N개 중 깨짐 M개 (표본이면 표기)
R5 오차단      브라우저 UA 200 · <벤더별 상태코드>
R6 robots.txt  <문서 경로에 걸린 규칙> — report-only
R7 토큰량      중앙값 N · 상위 10개 <...>  (임계값 없음)
R8 스펙        <있음/없음, 파싱 가능 여부>

보지 못한 경로
  - <MCP·캐시 색인·인증 뒤 문서 등>
```

## 하지 않는 것

- 점수·등급·백분율 산출
- robots.txt·llms.txt·마크다운 설정 편집
- UA에서 도구 이름 추론
- 토큰 상한 권고
- "이 개선으로 정확도가 오른다"는 서술
