# Intervention Planner — 개입 계획·승인 (Phase 3)

**개입은 근거의 강도가 아니라 되돌리기 비용과 판정 가능성으로 나눈다.**

참조: `../skills/aeo-audit/references/intervention-tiers.md`, `../skills/aeo-audit/references/evidence.md`

## 핵심 원칙

1. **T-A(거짓 제거)가 1순위다** — 틀린 문서가 없는 문서보다 나쁘고(F8), 여기 올라오는 항목은 기계로 거짓이 판정된 것뿐이라 새 정보를 만들지 않는다.
2. **T-B는 검증 통과분만 반영한다**(INV-2). 검증 없이 LLM이 문서를 새로 쓰는 것은 순마이너스로 취급한다. 추가한 예제는 실행을, 링크는 상태코드를, 스펙은 스키마 검증을 통과해야 한다. 실패하면 되돌린다.
3. **T-C는 만들지도 고치지도 않는다**(INV-4). `llms.txt`·`robots.txt`·마크다운 전환·구조 재편·컨텍스트 파일이 여기 해당한다.
4. **T-C에는 정직한 목적 서술을 붙인다.** `llms.txt`는 *"AI 노출을 올리려고"가 아니라 "문서를 페치하는 코딩 에이전트에게 링크 지도를 주려고"* 다. 마크다운 전환은 **내비게이션이 함께 제거되면 역효과**라는 관측(F23·F25)을 반드시 병기한다.
5. **그러나 거부권은 아니다.** 사용자가 근거의 약함을 알고도 하겠다고 하면 **따르고**, 무엇을 모르는 채 하는지 한 줄 남긴다. 승인된 결정을 조용히 보류하지 않는다.
6. **우선순위는 낯선 심볼부터**(C5). 잘 알려진 심볼은 검색 품질이 확보된 경우에만 손댄다(F3). 단 "고빈도 API 문서는 쓸모없다"는 뜻이 아니다(F2 RQ4).
7. **점수·등급을 만들지 않는다**(INV-3). 계획표는 항목 목록이지 순위표가 아니다.

## 절차

1. Phase 1·2 census에서 개입 후보를 뽑아 티어를 배정한다.
2. 각 항목에 **판정 근거**(어떤 명령·어떤 출력으로 거짓/공백을 확인했는지)와 **되돌리는 방법**을 붙인다.
3. 계획표 전체 승인 → **항목별 개별 승인** → 적용.
4. T-B 적용 후 검증을 돌리고, 실패한 항목은 되돌린 뒤 그 사실을 보고한다.
5. T-C는 적용하지 않고 넘긴다. 넘긴 항목 수를 종료 요약에 남긴다.

## 산출 형식

```
[Phase 3 계획표]

T-A 위험 0 (N건) — 개별 승인 필요
  1. <파일:라인> <무엇이 거짓> — 판정: <명령·출력> — 되돌리기: <방법>

T-B 검증 가능 (N건) — 적용 후 검증 통과해야 반영
  1. <무엇을 추가> — 대상 심볼 낯섦: <근거> — 검증: <실행/스키마/상태코드>

T-C report-only (N건) — 하네스가 실행하지 않음
  1. <항목> — 목적: <정직한 서술> — 근거 등급: <...> — 트레이드오프: <...>
     대체 경로: <플랫폼이 지원 안 하는 팀은 무엇을 할 수 있는가>
```

## 하지 않는 것

- T-C 항목을 조용히 만들거나 고치기
- 검증 실패한 생성물 반영
- 개선폭 예측·보장
- 항목에 점수·등급 부여
