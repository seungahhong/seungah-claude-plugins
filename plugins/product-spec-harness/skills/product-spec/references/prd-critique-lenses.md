# PRD 비평 렌즈 (확정 전 약점 색출 기준)

Phase 2의 **비평** 단계(`prd-critic`)가 따르는 기준이다. 대상은 **이번 회차에 만든 PRD 초안(§1~§6) 한 장**이며, 사용자 스토리는 아직 존재하지 않는다. 목표는 문서를 무너뜨리는 것이 아니라 **확정하기 전에 약한 고리를 드러내는 것**이다. 모든 산출 문서는 한국어로 작성한다.

---

## 이 단계가 정직하게 주장할 수 있는 것

초안을 만든 쪽과 비평하는 쪽은 같은 컨텍스트를 읽는다. 그래서 이 비평이 **"PRD 품질을 높인다"고 주장하지 않는다.** 정직하게 주장할 수 있는 것은 하나다 — **지적과 그 처리 결과(반영/질문/수용)가 문서에 남는다.**

- 차단 사유를 4종으로 고정한 것은 그 항목들이 **문서만 보고 예/아니오로 판정할 수 있는 성질**이기 때문이지, 이 단계가 그것들을 높은 확률로 잡아낸다고 측정했기 때문이 아니다(탐지율은 측정하지 않는다).
- 주관적 판단이 필요한 결함(예: 목표와 요구가 정면으로 어긋남)은 이 단계가 **차단하지 못한다**. 아래 [차단 사유 닫힌 목록](#차단-사유--닫힌-목록-4종)의 트레이드오프를 참조.
- **점수·백분율·완성도 등급·커버율을 산출하지 않는다.** 이 시점엔 스토리가 없어 커버율의 분모 자체가 없다. 쓸 수 있는 것은 `n건` 카운트뿐이다.

---

## 비평 렌즈 C-1 ~ C-7

매 회차 7개 렌즈를 전수로 훑는다. **보완할 점 점검표가 없으면**(모드 B이거나, 모드 A에서 사용자가 Phase 1 평가를 거절한 경우) **C-7은 '해당 없음 — 점검표 없음'** 으로 표기하고 결함으로 세지 않는다. 점검표를 스스로 만들어 감사하지 않는다 — 그것은 사용자가 방금 거절한 Phase 1 작업을 다시 하는 것이다.

| # | 렌즈 | 한 줄 정의 |
| --- | --- | --- |
| **C-1** | **문제–목표 정합** | §1의 문제가 §2의 목표·지표로 이어지는가. 문제에 없던 목표 / 목표로 이어지지 않는 문제를 색출한다 |
| **C-2** | **범위 경계** | §3 Out이 비었는가. In과 헷갈릴 인접 항목이 Out에 없는가. §4 요구가 In을 넘어섰는가. **§4~§6에 기획 설계 금지 어휘(API·스키마·컴포넌트·캐싱 등 구현 수단)가 유입됐는가** — 등급 상한은 `수정권고` |
| **C-3** | **지표 관찰성** | 서로 다른 두 사람이 같은 데이터를 보고 같은 참/거짓 결론에 도달하는가. 기준선·목표값·측정 방법·측정 시점이 있는가 |
| **C-4** | **요구 완결성·원자성** | In 항목 중 요구로 전개되지 않은 것, 접속사로 묶인 복합 요구, 중복 요구, ID 누락·중복. **§6 마일스톤의 포함 요구 ID·관찰형 완료 판정**도 이 렌즈로 본다(비관찰형 완료 기준·요구 ID 없는 마일스톤) |
| **C-5** | **예외·경계 공백** | 정상 흐름만 적혀 있는가. 중복 / 자격 미달 / 권한 없음 / 데이터 없음 / 외부 지연·실패 5종의 제품 규칙이 있는가. **§4.1~§4.4 블록의 공백·모순**(빠진 여정 단계, 도달 불가 상태, 비어 있는 권한·정보 항목 행)도 이 렌즈로 본다 |
| **C-6** | **근거 추적·발명 감사** | 본문의 모든 수치·정책·사실이 문제 정의 카드·기획안·사용자 답변 중 **어디서 왔는가**. 출처를 댈 수 없는 값은 최우선 지적이다 |
| **C-7** | **보강점 반영 감사** *(점검표가 있을 때만)* | Phase 1 보완할 점 점검표의 미충족(`[ ]`) 항목이 **어느 섹션·어느 요구 ID로** 흡수됐는가. 미반영이면 사유는 무엇인가 |

**렌즈 밖은 지적하지 않는다.** 특히 다음은 이 단계의 축이 아니다.

- 사용자 스토리·요구↔스토리 커버리지·좋은 스토리 6가지 기준(INVEST) — **대상이 아직 존재하지 않는다.** Phase 4의 축이다. 인수조건은 Phase 5가 쓰고 Phase 6이 검증한다.
- 원본 기획안 자체의 착수 준비도 — Phase 1의 축이다. 같은 문장을 다시 평가하지 않는다.
- 기술 리스크 — **구현 방식·아키텍처 선택에서 오는 리스크**(성능 병목·확장성·취약점·운영 부하)는 이 하네스의 범위 밖이다. **단 §4에 적힌 NFR 문장 자체의 관찰성(C-3)과 근거(C-6)는 점검한다** — 주제어가 성능·가용·보안이라는 이유로 NFR 전체를 비평에서 빼지 않는다(그러면 §4의 절반이 한 번도 읽히지 않고 확정된다).

## 지적 표기 형식

지적 1건은 아래 한 줄 형식을 지킨다. **원문 인용이 없는 지적은 자동 드롭**한다(근거 없는 단정 방지).

```
#<일련번호> [차단|수정권고|참고][C-n] <위치: §섹션 또는 FR-n> — "원문 인용" — 처리분류(A|B|C) — <보완 제안(기존 것 보존·추가 우선)>
```

일련번호(`#1`, `#2`…)는 사용자가 게이트에서 `(3) 특정 항목만 지정해 수정`을 고를 때 항목을 가리키는 주소다. 번호가 없으면 지정할 수단이 없다.

### 처리 등급 3값

| 등급 | 의미 |
| --- | --- |
| **차단** | 이 상태로 확정하면 다음 단계가 추측해야 하거나 목표 달성 여부를 판정할 수 없다. **아래 닫힌 4종에만 부여 가능** |
| **수정권고** | 확정은 가능하나 스토리 단계에서 되묻거나 고쳐야 할 소지가 있다 |
| **참고** | 표현·용어 수준 |

심각도 점수·우선순위 숫자·성숙도 등급은 매기지 않는다.

### 처리분류 A / B / C — 발명을 막는 장치

각 지적이 **어떻게 해소되는 종류인지**를 반드시 분류한다. 이 분류가 없으면 다음 회차에 빈칸을 그럴듯한 숫자로 메우는 일이 벌어진다.

| 분류 | 의미 | 처리 |
| --- | --- | --- |
| **A** | 문서 내부에서 해소 가능(구조·중복·ID·문장·누락 전개) | 다음 회차에 해당 섹션 소유 단계가 고친다 |
| **B** | **사용자만 아는 사실**이 필요(수치·정책·기한·대상) | **고치지 않는다.** `[확인필요]` 마커로 남기고 질문 큐로 보낸다 |
| **C** | 이번 범위 밖 | **§5 가정·리스크로 이관**을 제안하고 종료한다(설계가 §5에 반영한다). 확정까지 §5에 반영되지 않으면 부록 B에 `[범위 밖 이관]`으로 남는다 |

**B를 A로 처리하는 것이 곧 발명이다.** 다음 회차가 돌면 C-6(발명 감사)이 이를 다시 본다 — 회차를 더 돌지 않고 확정하면 점검되지 않는다.

### 차단 사유 — 닫힌 목록 4종

`차단` 등급은 아래 4종에만 부여할 수 있다. **비평은 새 차단 사유를 만들지 못한다.**

1. **§3에 Out이 비어 있다** (Out 미기재는 모든 것을 In으로 오해하게 만든다)
2. **§2에 판정불가 성공지표가 남아 있다** (관찰로 참/거짓을 가릴 수 없다)
3. **요구 ID가 누락·중복됐거나, §3 In 항목 중 요구로 전개되지 않은 것이 있다** (Phase 3·4가 참조할 주소가 없다)
4. **출처 없는 수치·사실(발명)이 본문에 남아 있다**

> **이 목록을 닫아 둔 이유와 그 대가(정직히 명시)** — 비평 역할은 구조적으로 "결함 0건"을 내기 어려워, 회차마다 새 차단이 생기면 루프가 끝나지 않는다. 그래서 차단 사유를 **판정 가능한 4종으로 고정**해 종료를 보장했다. 대가는 명확하다 — **주관적 판단이 필요한 중대 결함은 최대 `수정권고`에 머문다.** 이는 결함 포착력과 종료 보장성을 맞바꾼 설계 선택이며, 숨기지 않는다. 그런 항목은 **최우선 권고 3가지**에 올려 눈에 띄게 만든다.

### 출력 상한

지적은 회차당 **최대 12건**(차단 → 수정권고 → 참고 순). 초과분은 절단하되 **"n건 절단함"을 반드시 표기**한다(조용한 절단 금지).

## 비평에는 거부권이 없다

- 비평은 **문서를 직접 고치지 않는다**(쓰기 권한 0). 지적과 제안만 낸다.
- 차단 지적이 남아 있어도 **사용자가 확정을 선택하면 그 즉시 확정한다.** 잔존 지적은 PRD 부록 B(알려진 제한사항)에 `[미해소 지적] {렌즈} — {한 줄}`로 기록하되, 그것을 이유로 진행을 막거나 조용히 보류하거나 재확인을 반복하지 않는다.
- 위험은 알리되 **감수 여부는 사용자가 정한다.**
- 지적 0건이면 칭찬형 코멘트 대신 **어떤 점검을 통과했는지 사실로만** 제시한다.

## 정체 가드 G1 ~ G3

같은 자리를 맴도는 루프를 구조적으로 끊는다.

| 가드 | 조건 | 처리 |
| --- | --- | --- |
| **G1 반복** | 새 회차 지적의 (렌즈 × 위치)가 직전 회차와 동일하고 처리분류도 그대로다 | 회차를 **더 권하지 않고** 잔존을 `[미해소 지적]`으로 부록 B에 기재한 뒤 사용자 판단을 구한다. **단 사용자가 그래도 한 번 더를 선택하면 경고 1줄만 병기하고 즉시 회차를 돈다**(거부·재확인 반복 금지) |
| **G2 증식** | **렌즈를 지정하지 않은 지적이 있다** | 7렌즈 밖에서 만들어진 지적으로 보고 **드롭**한다(드롭 건수 보고). **회차 판단에는 쓰지 않는다.** 건수 증가 자체는 가드가 아니다 — 직전 회차에 적용 못 한 렌즈가 있었다면(그때 '보지 못한 것'에 기록됨) 이번 회차의 증가는 정상이다 |
| **G3 무근거** | 원문 인용이 없다 | 카운트하지 않고 자동 드롭한다(드롭 사실 보고). **회차 판단에는 쓰지 않는다** — 인용 없는 지적 1건 드롭은 정체 신호가 아니라 정상 동작이다 |

드롭·절단은 **언제나 사실을 보고한다.** 조용한 삭제는 "전부 봤다"로 읽히는데 실제로는 아니다.

## 정직성 가드레일

- **효과를 약속하지 않는다.** "비평 루프를 돌리면 재작업이 N% 줄어든다" 류의 주장을 하지 않는다. 이 하네스는 그것을 측정하지 않으며, 회차 이력은 *변화의 기록*이지 *개선의 증거*가 아니다.
- **점수·백분율·성숙도 등급을 산출하지 않는다.**
- **수치·사례를 발명하지 않는다.** 입력에 없으면 지적이 아니라 `[확인필요]` 질문으로 되돌린다.
- 정량 근거를 인용할 일이 있으면 [`dor-review-rubric.md`](./dor-review-rubric.md)의 Honesty Guardrail(출처 등급·출처명·반대증거 병기, '개선 N%' 금지)을 그대로 따른다.
