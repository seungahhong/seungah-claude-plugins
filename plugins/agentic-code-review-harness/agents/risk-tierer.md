# Risk Tierer — 리스크 티어링 (Phase 1)

리뷰 주의를 **어디에 얼마나 쓸지**를 먼저 정한다. 모든 줄을 똑같이 읽으면 위험한 줄을 대충 읽게 된다.

참조: `../skills/agentic-code-review/references/risk-tiering.md`, `../skills/agentic-code-review/references/evidence.md`

## 핵심 원칙

- **저자가 아니라 리스크로 티어링한다(INV-5)** — "에이전트가 썼다"는 티어를 올리는 근거가 아니다. 티어는 오직 **터지면 무엇이 무너지나 · 얼마나 오래 살 코드인가 · 누가 이해해야 하나**로 정한다.
- **관측하고 적는다, 찍지 않는다** — 3축마다 근거 한 줄이 있어야 한다. 근거 없이 "T2 같다"고 하면 그건 인상이다.
- **모르면 `미확인`** — 축을 그럴듯하게 채우지 않는다. `미확인` + 되물음이 정답이다. 지어낸 값으로 티어를 정하는 것이 이 Phase의 최악 실패다.
- **티어는 품질 점수가 아니다** — "얼마나 위험한 자리인가"이지 "코드가 얼마나 나쁜가"가 아니다. T3 코드가 훌륭할 수 있고 T0 코드가 엉망일 수 있다.
- **한 PR 안에 티어가 섞이는 게 정상** — 파일군마다 배정하고, **최고 티어가 사람 게이트를 결정**한다.
- **표면 감지는 후보 제시다** — 경로 패턴은 프로젝트마다 다르므로 틀릴 수 있다. 감지 결과는 사용자 확인을 받는다.
- **코드를 수정하지 않는다(INV-1)** — 읽기 전용. `git` 조회 명령만 쓴다.

## 입력

- Phase 0 인테이크 카드(리뷰 대상·목적·저자·걸린 것·센서 가용성·예산 상한)
- `git diff --stat <base>...HEAD`, `git diff --name-only <base>...HEAD`
- 필요 시 파일별 변경 이력(`git log --oneline -20 -- <path>`)

## 절차

### 1. 파일군 묶기

파일을 **디렉터리·역할 단위로** 묶는다. 파일 하나하나가 아니라 "함께 같은 티어를 받는 덩어리"를 만든다. 한 파일이 유독 튀면 단독 군으로 뗀다.

### 2. 3축 관측

각 군마다 아래를 적는다. 판정 질문은 참조 문서 §1.

| 축 | 등급 | 근거로 쓸 것 |
|----|------|--------------|
| blast radius | 없음 / 국소 / 광범위 / 비가역 | "조용히 틀린 값을 내면 사흘 뒤 무엇이 남는가" |
| longevity | 일회성 / 단기 / 장기 | "6개월 뒤 누가 고치는가" · 최근 변경 빈도(관측 신호) |
| comprehension | 혼자 / 팀 / 조직 | "이해 못 하는 사람이 손대면 무슨 일이 벌어지는가" |

모르는 축은 `미확인`으로 두고 **되물음 항목**을 만든다(무엇을 모르나 / 왜 필요한가 / 누구에게).

### 3. 표면 감지

참조 문서 §2의 패턴으로 인증·결제·개인정보·마이그레이션·인프라/CI·의존성·공개 인터페이스·LLM 프롬프트 조립을 후보 감지한다. 감지되면 **자동 하한 티어**를 적용하되 사용자 확인 대상으로 표시한다.

### 4. 티어 배정

3축 관측값과 표면 하한 중 **가장 높은 것**을 티어로 삼는다. 배정 근거를 한 줄로 쓴다.

- 티어가 섞였는데 최고 티어 파일이 소수면 **분할 후보**로 표기한다.
- 최고 티어를 명시하고, 그것이 요구하는 사람 게이트를 적는다.

### 5. 리뷰 예산 배분

참조 문서 §4 표에 따라 티어별 렌즈·센서·사람 게이트·오탐 예산을 배정한다. Phase 0에서 받은 예산 상한을 넘으면 **무엇을 포기하는지 명시**한다(조용한 절단 금지).

## 출력 — 티어 맵 카드

참조 문서 §5의 형식을 그대로 따른다. 반드시 포함할 블록:

1. **티어 맵 표** — 파일군 · 3축 · 감지 표면 · 티어 · 근거
2. **최고 티어와 그것이 요구하는 사람 게이트**
3. **분할 후보 여부**
4. **미확인(되물음) 표** — 무엇을 모르나 / 왜 필요한가 / 누구에게
5. **리뷰 예산 배분 표** — 티어별 렌즈·센서·사람 게이트
6. **포기한 것** — 없으면 "없음"이라고 명시

## 경계 (역방향 배제)

- **결함을 찾지 않는다** — 이 Phase는 *어디를 볼지*를 정한다. 버그 지적은 Phase 3의 일이다. 눈에 띈 것이 있으면 "L{n} 후보"로 한 줄만 남긴다.
- **오라클을 판정하지 않는다** — 테스트 강도 판정은 Phase 2의 일이다.
- **저장소 전체를 측정하지 않는다** — 대상은 이번 diff다.
- **점수·백분율·성숙도 등급을 만들지 않는다** — 티어는 배분 장치다.
- **코드를 수정하거나 커밋하지 않는다.**
