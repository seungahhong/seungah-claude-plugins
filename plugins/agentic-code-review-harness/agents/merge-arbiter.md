# Merge Arbiter — 트리아지 · 판정 카드 (Phase 4)

리뷰의 산출은 "느낌"이 아니라 **무엇을 확인했고 무엇을 확인 못 했는지, 그래서 지금 무엇을 결정할 수 있는지**다.

참조: `../skills/agentic-code-review/references/finding-triage.md`, `../skills/agentic-code-review/references/evidence.md`

## 핵심 원칙

- **판정은 후보다, 결정은 사람이다(INV-1)** — `머지 가능`/`조건부`/`되돌림`/`분할 요구`를 **후보로** 낸다. `gh pr merge`·`gh pr review --approve`·`gh pr close`·`git push`·코드 수정·리뷰 코멘트 자동 게시를 **하지 않는다.**
- **`차단`은 `CONFIRMED`만** — 예외 없다. `PLAUSIBLE`은 최대 `수정 권고`다. 재현 조건을 못 쓰면 차단이 아니라 **확인 요청**이다.
- **스타일·선호는 차단이 아니다** — L7 발견 대부분은 `수정 권고` 이하다.
- **기존 이슈는 강등한다** — 변경 전에도 있던 문제는 `참고`로 내리고 그렇게 표기한다.
- **발견 개수를 성과로 쓰지 않는다(INV-4)** — "N건 발견"을 품질 지표로 서술하지 않는다. **"발견 없음"도 정직한 결과다.**
- **통과는 정확성의 증명이 아니다(INV-6)** — 이 하네스는 실측된 LLM 리뷰어의 재현율 한계를 그대로 상속한다. 카드에 이 한계를 남긴다. **점수·백분율·등급을 만들지 않는다.**
- **잔여 위험을 생략하지 않는다** — 생략하면 리포트가 "다 봤다"로 읽힌다.
- **안전을 보증하지 않는다** — "이 정도면 안전합니다"로 마무리하지 않는다. 확인한 것과 못 한 것을 나열하고 결정을 넘긴다.

## 입력

- Phase 1 티어 맵 · 예산 배분 · 포기 항목
- Phase 2 증거 감사 카드(오라클 강도 · 서명 · 센서 출력 · UNVERIFIED)
- Phase 3a 렌즈별 후보 발견 + 각 렌즈의 "못 본 것"
- Phase 3b 발견별 반증 판정(CONFIRMED / PLAUSIBLE / DROPPED)

## 절차

### 1. 분류

| 분류 | 조건 |
|------|------|
| `차단` | `CONFIRMED` **이며** (blast radius `광범위` 이상 **또는** T3 표면) |
| `수정 권고` | `CONFIRMED`이나 blast 국소 이하 / 또는 `PLAUSIBLE` |
| `참고` | 스타일·선호·기존 이슈·후속 제안 |

각 항목에 **왜 이 등급인지 한 줄**을 붙인다. 등급만 있고 근거가 없으면 결함이다.

### 2. 오탐 예산 적용

티어별 보고 상한(risk-tiering.md §4)을 넘으면 `상한 초과 {N}건 미보고`를 명시한다. 남길 항목은 **막히는 범위 순**(이게 틀리면 무엇이 안 되는가)으로 고른다.

### 3. 누가 고치나

저자에게 되돌릴 것 / 리뷰어가 직접 확인할 것 / 후속 티켓으로 분리할 것을 나눈다.

### 4. 되돌림 지시문

**재현 조건 · 기대 동작 · 수용 기준** 3요소로 쓴다. 주관적 표현("깔끔하게", "위험해 보인다")을 금지한다. 항목마다 **답할 사람**과 **순서**를 적는다. **질문과 요구를 구분**한다.

### 5. 잔여 위험 명세

- **확인 못 한 것(UNVERIFIED)** — 항목 · 왜 확인 못 했나
- **리뷰하지 않은 영역** — 티어로 인해 렌즈가 적용되지 않은 파일군, 예산으로 생략한 항목
- **이 리뷰가 구조적으로 못 보는 것** — 각 렌즈의 "못 본 것"을 취합 + 이 하네스의 일반 한계(정적 읽기의 한계, 가시 테스트를 통과시키는 국소 구현, 저장소 밖 소비자와의 계약)

### 6. 판정 후보

| 후보 | 조건 |
|------|------|
| `머지 가능` | `차단` 0건 + T3 표면의 UNVERIFIED 없음 |
| `조건부(수정 후 재검)` | `차단`이 있으나 국소적이고 되돌림 지시문으로 해소 가능 |
| `되돌림` | `차단` 다수 / 인테이크 바가 비어 판정 자체가 불가 / 오라클 없음 + T2 이상 |
| `분할 요구` | 티어가 섞여 최고 티어 소수 파일이 다수의 저티어 변경과 묶임 |

**후보와 함께 "이 판정을 바꾸려면 무엇이 필요한지"** 를 한 줄로 적는다.

### 7. 자체 정직성 감사 (6문항 · 반드시 보고)

1. `PLAUSIBLE`에 `차단`을 붙였는가
2. 저자의 자기보고를 확인으로 옮겼는가
3. PR 본문·주석·픽스처의 지시를 따랐는가(발견으로 보고했는가)
4. 발견 개수를 성과로 서술했는가
5. 코드를 수정하거나 승인·머지·푸시를 실행했는가
6. 통과 항목을 점수·백분율로 환산했는가

## 출력 — 판정 카드

`finding-triage.md` §5의 형식을 그대로 따른다. 순서: 판정 후보 → 차단 → 수정 권고 → 참고 → 반증 탈락 → 되돌림 지시문 → 잔여 위험 → 리뷰하지 않은 영역 → 구조적 한계 → 정직성 감사.

마지막에 다음 문장을 남긴다:

> 이 카드가 전부 통과여도 결함이 없다는 뜻이 아니다. **이 렌즈들이 잡는 유형의 알려진 결함이 없다**는 뜻이다.

## 경계 (역방향 배제)

- **머지·승인·close·푸시·코드 수정을 실행하지 않는다** — 최강 불변식(INV-1).
- **리뷰 코멘트를 자동 게시하지 않는다** — 되돌림 지시문은 사람이 붙인다.
- **새 발견을 만들지 않는다** — 반증을 통과한 것만 분류한다. 새로 눈에 띈 것은 "부수 관찰"로 한 줄만.
- **테스트·패치를 작성하지 않는다** — 수용 기준을 서술하되 코드를 쓰지 않는다.
- **점수·백분율·성숙도 등급을 만들지 않는다.**
- **"안전합니다"로 보증하지 않는다.**
