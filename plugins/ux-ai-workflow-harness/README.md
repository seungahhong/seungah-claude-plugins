# ux-ai-workflow-harness

UX 실무자(리서처·디자이너·UX 라이터·서비스 디자이너)가 **구체적인 UX 작업 하나에 생성형 AI를 어디까지 어떻게 쓸지** 단계별로 정하는 Claude Code 플러그인입니다. 단계마다 AI가 맡을지 사람이 맡을지 근거와 함께 판정하고, AI에 줄 지시문을 만들고, AI 초안을 UX 방법론의 알려진 실패 패턴으로 점검한 뒤, 사람이 맡을 단계와 확인 지점을 배정합니다.

NN/g의 ["Using AI for UX Work: Study Guide"](https://www.nngroup.com/articles/ai-work-study-guide/)(2026-09)와 링크된 원문 약 40편을 읽고, 원문이 인용한 1차 연구와 대조해 근거 등급을 붙였습니다.

## 설치

```bash
claude plugin add seungahhong/seungah-claude-plugins
```

## 한 문장 원칙

> **AI는 UX 작업을 압축할 수 있지만, 팀이 사용자에게서 배우는 단계는 대신할 수 없다.**

"리서치를 AI로 해도 되나"에는 답할 수 없습니다. **인터뷰 가이드 초안**, **인터뷰 진행**, **인터뷰 해석**은 각각 답이 다릅니다. 그래서 이 하네스는 작업이 아니라 **단계**를 판정합니다.

## 사용법

```
/ux-ai-workflow
```

첫 질문은 세 가지이고 하나씩 묻습니다. **어떤 UX 작업인가**, **그 결과로 누가 무엇을 결정하는가**, **참가자 원자료(녹취·응답 등)가 AI에 들어가는가**. 산출물 하나만 검토받으러 오면 첫 질문만 묻고 나머지는 잠정값으로 둡니다. "이거 AI로 해도 돼?"형 질문이면 위임 지도만 받고 끝낼 수 있습니다.

### 인테이크 + 4단계

| Phase | 하는 일 |
|---|---|
| **0 인테이크** | 작업·결정·참가자 원자료가 AI에 들어가는지를 한 번에 한 질문씩. 원하면 AI 초안을 보기 전에 **자기 첫 판단을 한 줄** 남깁니다(건너뛰어도 됩니다) |
| **1 위임 지도** | 단계마다 7개 테스트로 4개 레인 중 하나를 정합니다 |
| **2 맥락·지시 설계** | AI가 맡는 단계마다 CARE 프롬프트(맥락·요청·규칙·예시)를 단계로 쪼개 만들고, 방법론 규칙을 붙입니다 |
| **3 AI 초안 점검** | 사용성 과제 유도, 설문 응답 부담, 합성 사용자 아첨, 프랑켄슈타인 레이아웃, 톤 과장 같은 **방법론별 점검표**로 확인합니다 |
| **4 사람 체크포인트** | 사람 단계마다 담당·시점·팀 학습 장치, AI 초안마다 사람 확인, 모든 산출물에 출처 라벨 |

### 4개 레인

| 레인 | 예 |
|---|---|
| **L1 AI에 넘김** | 전사, 템플릿 채우기, 테스트용 목 데이터, 문안 대안 |
| **L2 AI 초안 + 사람 검수** | 연구 질문 후보, 스크리너·과제·설문 초안, 1차 코딩 |
| **L3 사람이 한다** | 반구조화 인터뷰 진행, 사용성 테스트 관찰, 디브리프, 해석, 결정 |
| **L4 AI로 대체하지 않음** | 합성 사용자로 컨셉 검증, 트랜스크립트만으로 사용성 분석, AI가 사용성 테스트 진행 |

### 7개 테스트

학습(직접 하면 팀이 배우는가) · 진실 기준(사실이 기준인가 발산이 기준인가) · 데이터 종류(행동인가 발화인가) · 책임(세부를 책임지는가) · 반복성(다시 하는가) · 도메인(니치인가) · 검수 역량(오류를 알아볼 사람이 있는가).

## 근거를 대조하며 고친 것

| 흔한 말 | 원 출처가 말하는 것 |
|---|---|
| "AI와 혼자 하면 팀만큼 좋은 아이디어가 나온다" | P&G 776명 실험에서 **평균** 품질은 그랬습니다. 다만 아무도 AI를 쓰지 않은 개인 대비 **최상위 10% 해결안 비율이 유의하게 늘어난 것은 사람 2명 + AI뿐**이었습니다. 개인 + AI는 유의하지 않았고, 팀+AI와 개인+AI의 직접 차이도 통상 기준에서는 유의하지 않았습니다 |
| "디지털 트윈·합성 사용자가 거의 사람처럼 답한다"(X2) | 자주 인용되는 수치는 참가자 **본인이 2주 뒤 다시 답한 일관성 대비** 비율이고, 같은 사람을 2시간 인터뷰해 만든 트윈입니다. 논문이 2026년에 개정되며 값도 바뀌었습니다(X15). 실제 응답자의 인구통계 분포만 맞춰 만든 합성 사용자는 추세는 맞고 평균 차이는 작았지만 **분산이 작아 하위집단·극단값을 보기 어렵습니다** |
| "AI가 생산성을 크게 올린다"(X1) | 흔히 인용되는 2023년 수치는 서로 무관한 세 연구를 재분석한 평균이고, 가이드 자체가 스냅샷이라고 밝힙니다. 2025년 초 숙련 개발자 무작위 실험에서는 AI를 쓴 쪽이 더 오래 걸렸는데 본인들은 빨라졌다고 믿었습니다(후속 연구는 지금은 더 빨라졌을 가능성을 언급). 효과는 체감이 아니라 소요 시간으로 재야 합니다 |
| "UX 맥락 파일(UX.md)을 주면 AI 디자인이 좋아진다" | 저자가 **가설**로 제안했고, 공개된 실험이 없습니다 |
| "AI UX 감사가 70% 맞으면 쓸 만하다"(X7) | 문제는 수치가 아니라 **어느 30%가 틀렸는지 알 수 없다는 것**입니다 |

## 정직성 불변식

- **학습 단계는 기본적으로 사람에게** — 진행·관찰·디브리프·해석·결정. 단 **경고이지 거부권은 아닙니다.** 옮기기로 하면 따르고, 무엇을 잃는지 기록합니다.
- **출처를 섞지 않습니다** — 합성 데이터·모델 추정·목 데이터를 실제 사용자 결과로 표기하지 않습니다.
- **AI 초안은 초안입니다** — 이 하네스의 점검도 최종 확인이 아닙니다. 설문은 실제 사람 파일럿, 과제는 사용자가 지정한 검수자 검토를 배정합니다(생략하기로 하면 따르고 기록합니다).
- **행동은 텍스트로 대체되지 않습니다.**
- **지어내지 않습니다** — 사용자 발견·인용·수치·출처를 입력 없이 만들지 않고 `[확인 필요]`로 남깁니다.
- **효과를 약속하지 않고 점수를 만들지 않습니다.**
- **참가자 데이터를 보호합니다** — 외부 AI 도구로 보내기 전 동의 범위·조직 정책·개인정보 정제 확인을 사람 단계로 둡니다.

## 이 하네스가 주장하는 것

두 가지뿐이고, 둘째는 실제 숫자로 적습니다. **각 단계를 누가 맡을지와 왜 그런지를 근거와 함께 적었다**, **점검한 초안 n개에서 알려진 실패 패턴을 확인했고, 점검하지 않은 단계와 담당 미정 확인이 몇 건 남았는지 적었다.**

## 범위 밖

PRD·사용자 스토리 작성, 인수조건을 Figma 화면 구조로 옮기기, 임의 도구용 프롬프트 최적화, 사람↔AI 에이전트 팀의 감독 체계 설계, LLM 출력 채점 신뢰성 설계, AI *제품*의 UX 설계, 코드 구현·리뷰·커밋.
