# 작업 유형 카드

Phase 1이 사용자의 작업을 단계로 쪼갤 때 출발점으로 쓰는 카드. **카드는 기본값이지 정답이 아니다** — 사용자의 실제 작업이 카드와 다르면 사용자의 작업을 따른다. 근거 번호는 [evidence.md](./evidence.md), 점검표 번호는 [output-pitfalls.md](./output-pitfalls.md).

**점검표 칸은 기본 연결이다** — `output-critic`은 실제 산출물 유형으로 점검표를 고른다(사용자가 레인을 옮긴 단계도 마찬가지 — 예: 해석을 L2로 옮기면 P-INSIGHT).

**레인 칸에는 L1~L4만 쓴다.** 조건에 따라 달라지면 "L1 (조건: … 이면 L2)"처럼 조건과 레인을 함께 적고, 그 조건은 인테이크 카드 값으로 정한다. **점검표 칸은 AI가 만든 산출물이 있는 L1·L2 행에만** 붙는다 — L3 행의 사람 검토는 Phase 3 점검 결과를 입력으로 받는다.

카드에 없는 작업은 가장 가까운 카드를 고르지 말고 **단계를 직접 쪼갠 뒤** [delegation-tests.md](./delegation-tests.md)의 테스트만 적용한다.

## R-PLAN 리서치 계획

"계획 전체를 한 번에 만들어 달라"고 하지 않는다(E9). 순서를 지킨다.

| 단계 | 기본 레인 | 메모 | 점검표 |
|---|---|---|---|
| 맥락 정리(조직·제품·알고 싶은 것) | L3 | 사람이 쓴다. AI는 빠진 항목을 되물을 수 있다 | — |
| 데스크 리서치 시작 | L2 | 출발점이지 최종 출처가 아님. **1차 출처를 요구하고 직접 연다**(E6·E8) | P-DESK |
| 연구 질문 후보 | L2 | 필요한 것보다 많이 받고, 외부 문서로 옮겨 고른 뒤 **고른 것만 들고 새 세션**(E9) | — |
| 방법 후보와 질문↔방법 대응 | L2 | "어떤 질문에 어떤 방법인지·이유"를 묻는다. NN/g 관찰상 행동 질문에도 인터뷰를 제안하는 경향이 있다(E9) | P-METHOD |
| 방법 결정 | **L3** | 후보를 보고 사람이 정한다 | — |
| 포함 기준 | L2 | 질문·방법이 정해진 뒤에만 | — |
| 스크리너 | L2 | 위장용 보기 포함 지시(E9) | P-SCREENER |
| 사용성 과제 | L2 | **유도·프라이밍이 가장 흔한 실패**(E9·E21) | P-TASK |
| 인터뷰 가이드 | L2 | 질문 과다·유도 질문·인터뷰와 사용성 테스트 혼동 점검(E21) | P-GUIDE |
| 모집·일정 문안 | L1 (조건: 조직 템플릿 없으면 L2) | 템플릿이 있으면 주고 채우게 한다(E8) | P-RECRUIT |
| 동의 범위 결정 | **L3** | 녹취를 외부 AI에 넣을지, 디지털 트윈에 쓸지 등 **무엇에 동의받을지**는 사람이 정한다(E18·INV-8) | — |
| 동의서 문안 | L1 (조건: 조직 템플릿 없으면 L2) | 템플릿 없이 AI가 쓰면 권한 범위 오류를 대조할 기준이 없다 — 법무·개인정보 담당 검토를 검수자로 | P-RECRUIT |

## R-SYNTH 합성 사용자·디지털 트윈 요청

사용자가 "합성 사용자로 해보자"고 하면 먼저 **무엇에 쓸지**를 묻는다(E12·E18). **대상이 니치·전문 사용자군이면(D6) 용도와 무관하게 L4**다.

| 용도 | 레인 | 이유 | 점검표 |
|---|---|---|---|
| 새 사용자군 공부, 탐색 주제 고르기, 인터뷰 가이드 파일럿 | L2 | NN/g가 인정한 준비 용도(E12) | P-SYNTH |
| 가설·프로토 페르소나·프로토 여정지도 | L2 | `합성 데이터 · 가설` 라벨. 실제 리서치 후 갱신 전제(E12) | P-SYNTH |
| 컨셉 검증·우선순위·의사결정 | **L4** | 아첨·이상화·모든 것이 중요함(E12), 추세는 맞고 분산이 작음(E15) | — |
| 이미 인터뷰한 사람들의 결측 응답 보완 | L2 | `모델 추정` 라벨. 보간은 되나 새 질문엔 약하다(E14). **참가자 동의 범위 확인**(E18) | P-SYNTH |
