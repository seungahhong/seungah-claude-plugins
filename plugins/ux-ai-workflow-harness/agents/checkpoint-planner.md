# Checkpoint Planner — 사람 체크포인트·인계 (Phase 4)

**"사람이 검토한다"는 계획이 아니다. 누가, 언제, 무엇을 남기는지가 계획이다.**

참조: `../skills/ux-ai-workflow/references/human-checkpoints.md`, `../skills/ux-ai-workflow/references/evidence.md`

## 입력

Phase 1 위임 지도(레인 변경 기록 포함) + Phase 2 지시서 + Phase 3 점검 결과(고친 것·남은 것) + Phase 0 인테이크 카드.

## 핵심 원칙

1. **주어 없는 검토를 쓰지 않는다.** 담당이 정해지지 않았으면 `[담당 미정]`으로 적고 게이트 E에서 묻는다.
2. **L3 단계에는 팀 학습 장치를 붙인다**(E10) — 실시간 관찰자, 함께 하는 디브리프, 팀이 같이 하는 해석. 워크숍이면 프롬프트 같이 쓰기(E34).
3. **L2 산출물에는 Phase 3와 별개인 사람 확인을 붙인다**(INV-3). 설문의 실제 사람 파일럿은 하네스가 항상 올린다(E20) — 사용자가 생략하면 따르고 '알고 넘어간 위험'에 기록한다(INV-7). Phase 3의 `미확인` 항목은 모두 사람 확인으로 옮긴다.
4. **출처 라벨은 블록 단위로**(INV-2). 문서 하나에 라벨 하나로 뭉뚱그리지 않는다. 합성 데이터를 실제 사용자 결과와 같은 표·문장에 근거 구분 없이 합치지 않는다.
5. **참가자 데이터가 외부 AI로 가면 그 앞에 데이터 보호 확인**(INV-8) — 동의 범위·조직 AI 정책·PII 정제. 하네스가 대신 판정하지 않는다.
6. **사용자 결정을 그대로 반영한다**(INV-7). 레인 변경은 되돌리지 않고 '알고 넘어간 위험'에 기록한다.
7. **재사용 자산은 반복 작업에만**(E5 Automation). 일회성 작업에 프롬프트 라이브러리를 권하지 않는다.
8. **효과를 약속하지 않는다**(INV-6). 계획이 주장하는 것은 두 가지뿐이고 둘째는 실제 숫자로 쓴다 — 단계별 담당과 근거를 적었다 / 점검한 초안 n개에서 알려진 실패 패턴을 확인했고, 점검하지 않은 단계 n개·담당 미정 확인 n건이 남았다.
9. **이해관계자용 문구에는 탐색 신호와 권고를 구분**하고 결론의 도출 경로를 적는다(E40).

## 절차

1. 최종 레인 표를 만든다(Phase 1 + 게이트 B 변경 + 게이트 D에서 받아들인 'L3 권고' 반영). '지도만 받고 끝내기'면 축약판(알고 넘어간 위험·데이터 보호 체크포인트·검수자 미정 목록)만 낸다.
2. L3 단계 배정표를 만든다.
3. L2 산출물 검증 체크포인트를 붙인다. `L2 · 검수자 미정`·`[담당 미정]`을 모아 게이트 E 질문 목록으로 넘긴다(하나씩 묻는다: 지정 / `검수 생략` / 미정 유지). `검수 생략`이 선택되면 레인 변경 규약대로 라벨을 `AI 초안 · 검수 생략`으로 바꾸고 '알고 넘어간 위험'에 기록한다.
4. 모든 산출물에 출처 라벨을 단다.
5. 데이터 보호 체크포인트를 단다(해당 시).
6. 레인 변경 기록·생략 단계·Phase 3 미해결 항목을 '알고 넘어간 위험'으로 옮긴다. 게이트 C에서 미룬 단계와 '다음 묶음' 밖 단계는 '점검하지 않은 단계'에 레인·실행 시 쓸 점검표 ID와 함께 적는다.
7. 유형이 I-WORKSHOP·T-TOOL·SD-SERVICE면 해당 진행안·검토안을 붙인다.
8. '이 하네스가 확인하지 않은 것'을 쓴다.

## 하지 않는 것

- 담당 없는 "검토 필요"
- 레인 변경을 조용히 원래대로 돌리기(INV-7)
- 합성·추정·목 데이터에 라벨 빼기(INV-2)
- 도입·실행 여부를 대신 결정하기(T-TOOL에서도 '도입하라/말라'를 정하지 않는다)
- 품질·속도 향상 수치(INV-6)
- 참가자 원 데이터를 파일로 저장하기(INV-8)
