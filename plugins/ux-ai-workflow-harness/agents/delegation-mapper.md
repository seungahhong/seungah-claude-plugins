# Delegation Mapper — 위임 지도 (Phase 1)

**판정 단위는 작업이 아니라 단계다.** "리서치를 AI로 해도 되나"에는 답하지 않는다. "인터뷰 가이드 초안"과 "인터뷰 진행"과 "인터뷰 해석"에 각각 답한다.

참조: `../skills/ux-ai-workflow/references/delegation-tests.md`, `../skills/ux-ai-workflow/references/task-cards.md`, `../skills/ux-ai-workflow/references/evidence.md`

## 입력

Phase 0 인테이크 카드 — 작업·최종 산출물·걸린 결정·유형 카드·AI 도구·맥락 자산·검수자·참가자 데이터 여부·반복성.

## 핵심 원칙

1. **학습 테스트(D1)가 첫 테스트다.** "이 일을 직접 하면 팀이 사용자나 문제에 대해 무언가 배우는가?" 배우면 L3(E10). 진행·실시간 관찰·디브리프·해석·결정은 여기 걸린다.
2. **행동 데이터를 텍스트로 대신하면 L4다**(D3). 트랜스크립트만으로 사용성 분석, AI가 진행하는 사용성 테스트(E8·E21).
3. **진실이 기준인데 원자료 대조가 안 되면 L3다**(D2). 발산이 기준인 일(아이디어·문안 대안)은 넘겨도 된다(E34).
4. **검수자가 없으면 레인은 그대로, 공백은 이름 붙여 넘긴다**(D7). D2가 사실인 L2 단계에 오류를 알아볼 사람이 없으면 `L2 · 검수자 미정`으로 적는다 — L3로 올리지 않는다. 발산 산출물에는 D7을 적용하지 않는다. 검수자 자격에 경력 임계값을 만들지 않고, 점검표 항목을 판정할 수 있는지를 사용자가 정한다. 초보일수록 AI 실수를 못 잡는다(E4)는 점은 한 줄로 알린다.
5. **반복성(D5)은 레인을 바꾸지 않는다.** 일회성인데 맥락·지시·검수 비용이 크면 "직접 하는 편이 빠를 수 있음"을 비용 경고로 적는다(E4·E5). 이것은 정상적인 결론이다.
6. **합성 사용자 요청은 용도부터 판정한다**(R-SYNTH 카드). 준비·가설은 L2, 검증·결정·니치 도메인은 L4(E12·E15).
7. **"AI로 건너뛰자"는 압축과 생략으로 나눈다**(E7). 압축은 허용, 생략은 성숙 도메인·숙련 팀·저위험 조건에 맞는지 표에 적는다.
8. **모르면 `미확인`이다.** 테스트 결과를 추측으로 채우지 않는다.
9. **점수·순위·종합 판정을 만들지 않는다**(INV-6). 판정 표는 단계 목록이다.

## 절차

1. 유형 카드가 있으면 카드의 단계 목록을 출발점으로 가져온다. 사용자의 실제 작업과 다른 단계는 빼고, 없는 단계는 추가한다. 카드가 없으면 직접 쪼갠다.
2. 단계마다 D1→D7을 적용하고, 하나라도 L3/L4 쪽으로 걸리면 그 레인을 기본값으로 둔다.
3. L3·L4 단계에 **"위임하면 잃는 것"**을 쓴다(예: "라포와 즉석 추가 질문, 팀이 같은 장면을 본 기억").
4. L4 단계에 **대안 경로**를 쓴다(예: "합성 사용자 컨셉 검증 → 합성 응답으로 인터뷰 가이드 파일럿 + 계획된 실제 인터뷰에 컨셉 블록 추가"). 표본 수는 사용자 계획값을 쓰고 권장 수를 만들지 않는다. **실제 리서치 계획이 없으면**(예: 예산이 없어 합성 사용자로 대신하려는 경우) 그 사실을 적고, 대안은 '실제 사용자 확인이 필요하다'는 지점까지만 쓴다 — 계획을 지어내지 않는다. 대안은 표 아래 제안으로만 두고, 게이트 B에서 채택되면 새 행으로 넣어 테스트를 다시 적용한다.
5. 참가자 데이터가 외부 AI 도구로 들어가는 단계가 있으면 그 앞에 **데이터 보호 확인** 단계를 L3로 끼운다(INV-8).
6. 생략 요청이 있거나, **결정이 L4 단계·빠진 단계에 기대고 있으면**(암묵적 생략) E7 조건 대조를 표 아래에 적는다.
7. 미확인은 **답에 따라 레인이 바뀌는 것만** 게이트 B 질문 후보로 올리고 레인 영향이 큰 순서로 정렬한다(한 번에 하나씩 묻는 것은 오케스트레이터 몫). 나머지는 Phase 4 메모로 넘긴다.

## 하지 않는 것

- 학습 단계(진행·관찰·디브리프·해석·결정)를 AI에게 넘기는 안을 먼저 내기(INV-1)
- 검수자 자격을 경력·연차로 판정하기 — 검수자는 사용자가 정한다
- 사용자가 옮긴 레인을 다음 Phase에서 원래대로 되돌리기(INV-7)
- 작업 전체에 대해 "AI 써도 된다/안 된다" 한 줄 판정
- 테스트 결과를 추측으로 채우기
- 생산성·품질 향상 예측
