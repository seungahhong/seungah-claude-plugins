# ux-ai-workflow-harness

UX 실무자가 **구체적인 UX 작업 하나에 생성형 AI를 어디까지 어떻게 쓸지** 단계별로 정하는 하네스. 사용자용 개요는 [README.md](README.md), 근거 정본은 [skills/ux-ai-workflow/references/evidence.md](skills/ux-ai-workflow/references/evidence.md).

> **한 문장 원칙** — AI는 UX 작업을 압축할 수 있지만, 팀이 사용자에게서 배우는 단계는 대신할 수 없다.

## Structure

```
.claude-plugin/plugin.json              # v0.1.0
agents/                                 # 모두 model: "opus"
  delegation-mapper.md                  # Phase 1 위임 지도 (D1~D7 → L1~L4)
  context-curator.md                    # Phase 2 CARE 프롬프트 + 방법론 규칙 묶음 + (반복 시) UX 맥락 팩
  output-critic.md                      # Phase 3 방법론별 점검표 (통과/미통과/해당없음/미확인)
  checkpoint-planner.md                 # Phase 4 담당·시점·팀 학습 장치·출처 라벨·데이터 보호
skills/ux-ai-workflow/
  SKILL.md                              # Phase 0~4 오케스트레이터 + INV-1~8
  references/
    delegation-tests.md                 # 4 레인 · 7 테스트 · 레인 변경 규약 · 압축 vs 생략
    task-cards.md                       # 작업 유형 카드 14종 (R-PLAN … SD-SERVICE)
    care-prompting.md                   # CARE 골격 · 지시 설계 규칙 8 · 방법론 규칙 묶음 · UX 맥락 팩
    output-pitfalls.md                  # P-COMMON · 리서치 · 설문 · 디자인 · 글쓰기 · 아이디에이션 점검표
    human-checkpoints.md                # 사람 단계 배정 · 검증 체크포인트 · 출처 라벨 11종 · 워크숍·도구 검토안
    evidence.md                         # 근거 정본 E1~E40 · 인용 금지 X1~X15 · UNVERIFIED
  scripts/
    check_evidence.py                   # E·X 앵커 · 금지 문구 · 점수 어휘 휴리스틱 검사 (금지 수치는 X번호 ±80자·'금지' ±25자 안에 있어야 허용)
evals/trigger-eval.json                 # 트리거 경계 28문항 (should 12 / should-NOT 16 — UX 산출물 단순 생성 요청 near-miss 포함)
```

## Conventions

- 4개 에이전트 전부 `model: "opus"`로 spawn한다. 매 Phase 승인 게이트를 통과한 뒤에만 다음으로 넘어간다.
- Phase 3 경로 (b)의 초안 생성은 **의도적으로 정의 파일 없는** `general-purpose` 서브에이전트(`model: "opus"`)에 Phase 2 프롬프트 본문만 준다. 하네스 규칙이 초안에 새어 들어가지 않게 하기 위해서다.
- **모든 수치·주장은 `references/evidence.md`의 E번호를 근거로 단다.** 거기 없는 수치는 산출물에 쓰지 않는다.
- `scripts/check_evidence.py`가 정의되지 않은 E·X번호, 인용 금지 문구, 점수 어휘를 검사한다(`*.md` + `plugin.json`). 금지 수치를 교정하려고 인용할 때는 근처에 X번호를 함께 적는다. 정규식 휴리스틱이라 통과가 위반 없음의 증명은 아니다. 문서를 고쳤으면 돌린다.
- 근거 등급은 **출처 유형**이다(`[PRIMARY]`/`[PRIMARY-VIA-NNG]`/`[PRACTITIONER-STUDY]`/`[PRACTITIONER-GUIDANCE]`/`[INDUSTRY-MEASURE]`/`[SNAPSHOT]`/`[HYPOTHESIS]`). 측정 항목에는 DV를 적는다.
- 판정은 통과/미통과/해당없음과, 판정할 수 없을 때의 `미확인`(사유 기재)뿐이다. 점수·백분율·성숙도 등급을 만들지 않는다.
- 커밋하지 않는다. 저장은 opt-in이고 참가자 원 데이터는 저장하지 않는다.

## 출발점 대비 교정한 것

- **스터디 가이드의 한 줄 요약**은 P&G 실험을 "AI를 쓴 팀이 AI를 쓴 개인보다 나았다"로 전하지만, 원 논문에서 팀+AI와 개인+AI의 차이는 평균에서도 최상위 10%에서도 통상 기준(p<.05)에서 유의하지 않았다(최상위 직접 비교 p≈0.06~0.08). 대조군 대비 최상위 비율이 유의하게 늘어난 것은 2인 팀+AI뿐이다(+9.2%p, 대조군 5.8%). NN/g 기사 본문은 이를 대체로 정확히 옮겼고, 기사 속 "AI 없는 팀이 개인+AI보다 최상위가 많았다"는 둘 다 유의하지 않은 점추정 비교다.
- 디지털 트윈 정확도(X2·X15)는 원 정확도가 아니라 **참가자 본인의 2주 재응답 일관성 대비** 정규화 값이고, 합성 사용자가 아니라 같은 사람을 2시간 인터뷰한 트윈이다. 논문이 개정돼(2026, 제목 변경) 인터뷰 기반 값이 v1과 최신판에서 다르다 — 버전을 함께 적는다.
- 2023 생산성 수치(X1)는 새 데이터가 아니라 서로 무관한 세 연구의 재분석 평균이다. 가이드 자체가 스냅샷이라고 단서를 달았다.
- Baymard GPT-4 감사의 "14%"는 라이브 페이지 기준인데 NN/g 전사는 입력 스크린샷 기준처럼 적었다(스크린샷 기준은 26%). 이후 AI 감사 도구 정확도 "50~70%"와 "50~75%"는 같은 Microsoft 연구를 두 출처가 다르게 옮긴 것이다(X14).
- UX.md는 저자가 **가설**로 제안한 것이고, "실험상 개선된다"는 문장에는 공개된 실험이 없다.
