# spec-to-figma-harness

유저스토리·인수조건(AC)을 입력으로 받아, **프론트엔드가 되묻지 않고 개발할 수 있도록 Figma에 무엇을 어떻게 반영해야 하는지**를 설계해 디자이너·FE 핸드오프 패키지로 내보내는 도메인 무관 인터랙티브 멀티 에이전트 하네스. 한 문장 원칙은 **"기획서의 시나리오는 상태 프레임으로, 기획서의 규칙은 레이어 어노테이션으로"** 이며, AC를 이분 분해하고 상태 카탈로그를 역방향 호명해 누락을 드러낸 뒤(Phase 1), Figma 구조·명명·flow·토큰 요구를 설계하고(Phase 2), 레이어별 어노테이션 문안을 쓰고(Phase 3), FE 1인칭으로 "여기서 멈춘다" 지점을 적대 검증한다(Phase 4). **Figma 파일을 만들거나 고치지 않는다** — 설계도까지가 산출이고 반영은 디자이너가 한다.

사용자용 개요·사용법은 [README.md](README.md), Phase 흐름·게이트·에이전트 팀의 정본은 [SKILL.md](skills/spec-to-figma/SKILL.md), 근거 정본은 [evidence.md](skills/spec-to-figma/references/evidence.md)다.

## Conventions (핵심 불변식)

- **INV-1 발명 금지(최강 불변식)** — 사용자 노출 문구 원문·API 필드·트래킹 이벤트명·수치 경계·권한 정의는 **입력에 있는 것만**. 없으면 `[기획 확인 필요]` + 되물음. 지어낸 마이크로카피는 디자이너가 그리고 FE가 구현해 **틀린 값이 스펙이 된다**.
- **INV-2 커버리지 ≠ 품질** — AC↔프레임 매핑 수는 누락 점검 장치이지 품질 보증이 아니다. "질문 0"·"재작업 N% 감소"는 측정 근거가 없어 **인용 금지**. 준비도를 **점수·백분율로 환산하지 않는다**(통과/미통과/해당없음 3값).
- **INV-3 디자인 결정 대행 금지** — *무엇이 필요한가*(상태·규칙·구조·이름)만 명세하고 *어떻게 보일지*(레이아웃·비주얼·톤)는 디자이너 몫. **Figma 쓰기 MCP 도구(`use_figma`·`generate_figma_design`·`create_new_file`·`add_code_connect_map`·`upload_assets`)를 호출하지 않는다.** 기존 파일은 델타 진단용 **읽기 전용**(`get_metadata` 먼저 → 좁힌 노드만 상세).
- **INV-4 도구 제약 정직** — Code Connect = Dev/Full seat + Organization/Enterprise, 어노테이션 *생성* = Full seat + can edit, `Ready for dev` view·`Completed` = Org/Enterprise. 못 쓰는 팀에 요구 항목으로 강요하지 않고 **대체 경로 병기**. 해당 항목은 '미통과'가 아니라 **'해당없음'**.
- **INV-5 되물음은 1급 산출물** — 빈칸이 있는 정직한 문서 > 채워진 추측. 되물음을 숨기고 매끈한 문서를 내지 않는다.
- **한 번에 한 질문** — 인테이크·되물음은 하나씩(번호 선택지·직전 답이 다음 질문 결정). 질문 목록 덤프 금지.
- **승인 게이트** — 매 Phase 종료 시 산출물 + 1줄 보고 후 승인. 파일 저장은 opt-in(`.claude/_docs/<슬러그>/`, 미리보기 후 승인), **커밋하지 않는다**.
- **근거는 evidence.md가 정본** — 등급(`[GOLD]`/`[SILVER]`/`[BRONZE]`/`[관행]`) 없는 사실 주장은 결함이다. 티켓 ID 명명·어노테이션 vs 댓글 분기는 **공식 근거 없는 실무 관행**으로만 서술하고 효과 수치를 붙이지 않는다. 인용 가능한 유일한 정량 수치는 Telerik/Progress 2025(n=225 자기선택·상관관계)뿐이며 4개 조건을 모두 충족해야 인용한다.
- **경계** — 이미 있는 디자인의 읽기 전용 검수·게이트 판정, Figma 컨텍스트 추출·파일화, PRD·유저스토리 작성, AC의 테스트 계층·QA 시나리오 전개, 코드 구현·리뷰·커밋은 범위 밖. 경계는 **범주로만** 서술하고 다른 플러그인을 이름으로 참조하지 않는다(독립 플러그인).
- **Phase 간 ID 소유권** — 프레임 *이름*은 Phase 2가, 핀 번호(`P#`)는 Phase 3이 발급한다. Phase 1은 상태 코드(`S-*`)·규칙(`R#`)·되물음(`Q#`)만 발급하고 프레임은 `(예정)`으로 적는다. Phase 3은 **Phase 2가 지목한 레이어 경로만** 쓰고 새 이름을 만들지 않는다(INV-1 연쇄 차단). 실물 없는 신규 레이어는 `(제안)` 표기.
- 4개 에이전트가 협업하는 하네스이므로 `agents/{name}.md`를 두고 SKILL.md의 **모든 Agent 호출에 `model: "opus"`를 명시**한다.
