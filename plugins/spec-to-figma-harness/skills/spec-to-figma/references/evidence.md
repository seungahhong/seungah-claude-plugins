# 근거 대장 (Evidence) — 이 하네스가 사실로 말해도 되는 것

이 문서는 `spec-to-figma` 하네스의 **사실 정본**이다. 다른 모든 참조 문서(`ac-to-state-matrix.md`·`figma-blueprint.md`·`annotation-templates.md`·`handoff-readiness.md`)와 4개 에이전트 산출물은 Figma 기능·플랜·수치를 말할 때 **여기에 있는 것만** 쓴다.

- 여기에 **없는** Figma 기능·수치·효과는 **쓰지 않는다.** 모르면 안 쓰는 것이 정답이다.
- 여기 **인용 금지 목록**에 있는 주장은 하네스 출력 어디에서도 사실로 말하지 않는다.
- 확인 시점: **2026-07**. 플랜·시트 정책은 자주 바뀐다(§7 재검증).

## 7. 하네스 출력 규칙 (5줄 요약)

1. **수치를 말할 땐 3종 세트** — `등급 + 출처 + 반대증거/한계`. 셋 중 하나라도 없으면 그 수치는 쓰지 않는다.
2. **"N% 개선·재작업 감소·질문 0" 금지** — 이 하네스의 효과를 정량으로 약속하지 않는다(INV-2).
3. **미확인 값은 `[기획 확인 필요]`** — 문구 원문·API 필드·트래킹 이벤트명·수치 경계·권한 정의를 추론으로 채우지 않는다(INV-1).
4. **관행은 관행이라고 말한다** — §6은 "실무 관행"이라고 밝히고 메커니즘까지만. 공식 근거로 포장하지 않는다.
5. **팀 플랜·시트 제약을 병기한다** — Code Connect(Org/Ent + Dev/Full seat), 어노테이션 생성(Full seat + can edit), `Ready for dev` view·`Completed`(Org/Ent). 못 쓰는 팀에는 **대체 경로**를 함께 준다(INV-4).

## 8. 재검증 주기

- **확인 시점: 2026-07.** Figma는 기능·시트·플랜 정책을 자주 바꾼다. 이 문서의 GOLD 항목도 **영구 사실이 아니다.**
- **사용 전 재확인이 필요한 것(우선순위 순)**
  1. **플랜·시트 제약** — Code Connect / `Completed` / `Ready for dev` view / 어노테이션 생성 권한. 팀에 요구 항목으로 넣기 **직전에** 공식 문서로 재확인한다.
  2. **MCP 도구 목록·개수(현재 23개)** — 도구가 추가·개명되면 읽기/쓰기 분류가 달라진다.
  3. **waitlist·베타 기능** — `Code Layers`(2026-07 waitlist). GA 여부를 확인하기 전에는 요구 항목으로 넣지 않는다.
- **재확인 방법** — §2·§3 표의 출처 URL을 직접 연다. 3자 블로그로 갱신하지 않는다(BRONZE로 GOLD를 덮어쓰지 않는다).
- **갱신 규칙** — 사실이 바뀌면 표의 행을 고치고 **확인 시점 날짜를 함께 갱신**한다. 근거를 못 찾으면 행을 삭제하거나 `[관행]`으로 강등한다. **불확실한 채로 GOLD에 남기지 않는다.**
