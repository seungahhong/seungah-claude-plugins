# AC → 상태 분해 매트릭스

인수조건(AC)을 **화면 상태**와 **레이어 규칙**으로 빠짐없이 쪼개기 위한 참조. Phase 1(`state-cartographer`)이 따른다.

## 0. 이분 분류 규칙 (가장 먼저)

> **기획서의 "시나리오"는 상태 프레임으로, 기획서의 "규칙"은 어노테이션으로.**

AC 한 줄을 읽고 아래 결정 규칙을 순서대로 적용한다.

| 판정 | 신호 | 산출 |
|------|------|------|
| **시나리오(→ 프레임)** | Then 절이 *눈에 보이는 화면 구성의 변화*를 말한다 — "~이 표시된다", "~화면으로 이동한다", "목록이 ~로 바뀐다", "안내와 버튼이 보인다" | 상태 프레임 1개(또는 그 이상) |
| **규칙(→ 어노테이션)** | Then 절이 *값·조건·경계·부수효과*를 말한다 — "20자까지만", "100px 이상이면", "이벤트가 발생한다", "URL에 유지된다", "200ms 동안" | 해당 레이어에 붙는 어노테이션 핀 1개 |
| **둘 다** | 조건이 화면 구성도 바꾸고 값 규칙도 갖는다 — "0건이면 빈 상태 안내와 '전체 보기' 버튼" + "버튼 클릭 시 필터 초기화" | 프레임 1 + 핀 1 이상 (**분할하고 둘 다 만든다**) |
| **판정 불가** | Then 절이 관찰 불가하다 — "자연스럽게", "직관적으로", "빠르게" | 프레임/핀을 만들지 말고 **되물음 목록**으로 올린다 |

**한 AC가 프레임 1개에 대응한다고 가정하지 않는다.** 하나의 AC가 상태 2~3개를 만드는 일이 흔하다(예: "필터를 선택하면 결과가 표시된다" → 결과 있음 / 결과 0건 / 조회 실패).

## 1. 상태 유형 카탈로그 (전수 체크)

각 스토리마다 아래 축을 **하나씩 호명**해 "이 스토리에 해당하는가 / 해당하면 AC가 있는가"를 판정한다. 해당하는데 AC가 없으면 **결함**이 아니라 **되물음**이다(기획에 확인).

### A. 데이터 상태 (거의 모든 목록·상세 화면에 해당)
| 코드 | 상태 | 흔한 누락 지점 |
|------|------|----------------|
| `S-DEFAULT` | 기본 — 데이터가 정상적으로 있는 화면 | 보통 유일하게 그려져 있는 상태 |
| `S-LOADING` | 로딩 — 최초 진입 / 필터 변경 / 더 보기 | 스켈레톤인지 스피너인지, 부분 로딩인지 전체 로딩인지 |
| `S-EMPTY` | 빈 상태 — 데이터 0건 | **최초부터 0건**과 **필터 결과 0건**은 문구·행동이 다르다(구분 필요) |
| `S-ERROR` | 에러 — 조회 실패·타임아웃 | 재시도 버튼 유무, 반복 실패 시 문구 변화 |
| `S-PARTIAL` | 부분 실패 — 일부 섹션만 실패 | 화면 전체 에러로 뭉개면 안 되는 경우 |

### B. 진행·전이 상태
| 코드 | 상태 | 흔한 누락 지점 |
|------|------|----------------|
| `S-SUBMITTING` | 제출 중 — 버튼 비활성/스피너 | 중복 제출 방지 표현 |
| `S-SUCCESS` | 성공·완료 — 토스트/전체 화면/인라인 | 토스트 **위치·표시 시간·문구 원문** |
| `S-PAGING` | 추가 로딩 — 무한 스크롤/더 보기 | 마지막 페이지 도달 표현 |

### C. 입력·검증 상태
| 코드 | 상태 | 흔한 누락 지점 |
|------|------|----------------|
| `S-INVALID` | 검증 실패 | 메시지 **위치**(필드 하단/상단 배너), 트리거 시점(입력 중/포커스 아웃/제출 시) |
| `S-DISABLED` | 비활성 | 왜 비활성인지 안내가 있는가 |
| `S-FILLED` | 입력 완료·활성화 | 활성 조건 |

### D. 권한·세션 상태
| 코드 | 상태 | 흔한 누락 지점 |
|------|------|----------------|
| `S-UNAUTH` | 비로그인 | 로그인 유도 화면인가 리다이렉트인가 |
| `S-FORBIDDEN` | 권한 없음 | 화면 자체를 숨기나 안내를 보이나 |
| `S-EXPIRED` | 세션 만료 | 만료 시점 사용자 입력 보존 여부 |

### E. 콘텐츠 경계 상태 (기획서가 정상 데이터를 전제해 서술하는 탓에 AC로 잘 내려오지 않는 축 — 정의되지 않으면 FE가 값을 추측하게 된다)
| 코드 | 상태 | 흔한 누락 지점 |
|------|------|----------------|
| `S-OVERFLOW` | 긴 텍스트 | 몇 줄에서 말줄임인지, 툴팁 유무, 최대 길이 |
| `S-MIN` | 최소 데이터 | 1건일 때 레이아웃이 깨지는가 |
| `S-MAX` | 최대 데이터 | 목록 상한, 배지 `99+` 규칙 |
| `S-MISSING-FIELD` | 선택 필드 누락 | 이미지 없음·닉네임 없음일 때 대체 표현 |

### F. 반응형·환경 (해당할 때만)
| 코드 | 상태 |
|------|------|
| `S-BP-*` | 브레이크포인트별(모바일/태블릿/데스크톱) — 레이아웃이 *재배치*되는 지점만 프레임으로 |
| `S-THEME-*` | 다크/라이트 등 테마 분기(있을 때) |

> **볼륨에 가점하지 않는다.** 축을 전부 호명하는 것과 프레임을 전부 그리는 것은 다르다. 해당하지 않는 축은 "해당 없음"으로 명시하고 넘어간다. 불필요한 프레임은 디자이너 비용이자 유지보수 부채다.

> **카탈로그는 닫힌 목록이 아니다.** 위 6축에 없는 상태(모달·선택기 열림, 디바이스 권한 요청, 오프라인, 동시 편집 충돌 등)가 이 스토리에 필요하면 **새 상태 코드를 발급**하고(`S-` 접두), 근거가 AC에 없으면 되물음으로 함께 올린다. 카탈로그에 없다는 이유로 누락을 덮지 않는다.

## 2. 규칙(어노테이션) 유형 카탈로그

시나리오가 아닌 AC와, AC에는 없지만 디자인만으로 알 수 없는 것들을 아래 6분류로 흡수한다. 상세 템플릿은 [annotation-templates.md](./annotation-templates.md).

| 분류 | 잡아내는 것 |
|------|-------------|
| 인터랙션/조건 | 트리거·조건 분기·표시/숨김 |
| 데이터 바인딩 | API 필드·포맷·정렬·말줄임 기준 |
| 검증 규칙 | 길이·허용 문자·에러 문구 **원문** |
| 모션/트랜지션 | duration·easing (가능하면 프로토타입으로 대체) |
| 트래킹 이벤트 | 이벤트명·파라미터 |
| 참조/예외 | 관련 AC 번호·재사용 화면·예외 처리 |

## 3. 커버리지 매트릭스 (Phase 1 산출물의 핵심)

프레임 **이름**은 Phase 2가 확정하므로 Phase 1에서는 `(예정)`으로만 적는다. 핀 번호(`P#`)는 Phase 3이 발급하므로 Phase 1에서는 규칙 ID(`R#`)로 연결한다.

```
| AC   | 유형        | 상태 코드      | 프레임(예정)          | 규칙 | 미확인 |
|------|-------------|----------------|-----------------------|------|--------|
| AC-1 | 시나리오    | S-DEFAULT      | 주문내역 · 기본       | R1   | –      |
| AC-2 | 시나리오    | S-LOADING      | 주문내역 · 로딩       | –    | 스켈레톤 형태 |
| AC-3 | 시나리오+규칙| S-EMPTY        | 주문내역 · 빈상태     | R2   | 안내 문구 원문 |
| AC-4 | 시나리오    | S-ERROR        | 주문내역 · 에러       | R3   | 재시도 정책 |
| –    | (AC 없음)   | S-OVERFLOW     | (프레임 필요?)        | –    | **되물음** |
```

> 프레임명 최종 형식은 `{티켓ID} / {화면} · {상태}`(가운뎃점)이며 Phase 2가 확정한다.

두 방향을 **모두** 채운다.
- **정방향(AC → 산출)**: 모든 AC가 최소 1개의 프레임 또는 핀에 연결됐는가. 연결 없는 AC = 누락.
- **역방향(축 → AC)**: 카탈로그 축 중 해당하는데 AC가 없는 것 = **되물음**(디자이너·기획에 확인할 질문).

## 4. 되물음 규칙 (발명 금지)

다음은 **절대 추론해서 채우지 않는다.** 확인되지 않으면 `[기획 확인 필요]` 플레이스홀더로 남기고 Phase 1 되물음 목록에 올린다.

- 사용자에게 노출되는 **문구 원문**(에러 메시지·빈 상태 안내·토스트·버튼 라벨)
- **API 필드명·엔드포인트·쿼리 파라미터 값**
- **트래킹 이벤트명**과 파라미터
- **수치 경계**(글자 수 제한, 스크롤 임계값, 재시도 횟수, 페이지 크기)
- **권한·역할 정의**와 그에 따른 분기

그럴듯한 마이크로카피를 지어내면 디자이너가 그대로 그리고 FE가 그대로 구현해 **틀린 값이 스펙이 된다**. 빈칸은 정직한 산출물이고, 채워진 추측은 오염된 산출물이다.

**발명이 아닌 것(허용)** — 카탈로그의 **표준 상태명**(로딩·빈 상태·에러·비활성 등)을 상태·프레임 이름으로 쓰는 것. 발명 금지의 대상은 *사용자에게 노출되는 값*이지 분류 어휘가 아니다. 반대로 화면의 **업무 명칭**(예: "정산 대기함")은 확인되지 않았으면 `[기획 확인 필요]`다.
