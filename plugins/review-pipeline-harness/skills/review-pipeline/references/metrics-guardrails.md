# 지표 · eval · 가드레일 · circuit breaker — Phase 5

목표는 **"변경당 사람 시간은 줄이고, revert는 전보다 늘지 않게"** 다(E5). 사람 시간 지표만 보면 비용이 사라진 게 아니라 **옮겨진 것**일 수 있다. 그래서 모든 절감 지표는 가드레일과 **짝**으로 둔다(INV-2).

## 1. 지표 짝

| 묶음 | 지표 | 정의 | 수집 수단(예) |
|------|------|------|----------------|
| **사람 시간** | H1 PR당 사람 승인 수 | median·p95. **봇 승인 제외** | `gh pr list --json reviews` → `scripts/pr_baseline.py` |
| | H2 PR당 사람 코멘트 수 | 봇 제외 | 같은 데이터 |
| | H3 사람 대기 시간 | PR 생성 → 첫 사람 리뷰, 생성 → 머지 | 같은 데이터 |
| **가드레일** | G1 revert율 | 기간 내 머지 PR 중 이후 revert된 비율 | revert PR 제목·커밋 메시지 규약 |
| | G2 인시던트율 | 기간 내 변경으로 귀속된 인시던트 수 | 인시던트 트래커(사용자 제공) |
| **리뷰어 품질** | Q1 응답 분류 비율 | convergence-and-noise N1 | 라벨·스레드 |
| | Q2 오경보 | N2 | 깨끗한 PR 실행 |
| **수렴** | C1 1회 통과 비율 · 5회 이상 비율 · 평균 라운드 | N3 | 리뷰 이벤트 |

- **H 지표를 낮추는 정책 변경은 G 지표 관측 수단이 있을 때만 제안한다.** G를 볼 수 없으면 "가드레일 없음 — 사람 0명 경로 비권장"을 경고한다(INV-2·INV-7: 경고이지 거부권 아님).
- G2(인시던트)를 추적하지 않고 G1(revert)만 보면, 회귀가 revert 대신 hotfix로 처리될 때 가드레일이 눈을 감는다 → Phase 6 A10.
- 목표값을 하네스가 정하지 않는다. **기준선**(Phase 0)과 **사용자가 정한 허용 범위**만 쓴다. Anthropic 수치는 목표값이 아니다(X3).

## 2. 기준선 스크립트

`scripts/pr_baseline.py`는 **사용자가 받은 JSON 파일**만 읽는다(네트워크 호출 없음). 수집 명령은 사용자가 승인 후 실행한다(읽기 전용).

```bash
gh pr list --state merged --limit 200 \
  --json number,title,author,createdAt,mergedAt,additions,deletions,reviews,comments \
  > prs.json
python3 scripts/pr_baseline.py prs.json            # 사람이 읽는 표
python3 scripts/pr_baseline.py prs.json --json     # 기계용
```

출력: H1(median·p95), H2, H3(첫 사람 리뷰까지·머지까지 median/p95), 크기 분포, revert 제목 PR 비율(G1의 **하한 근사** — 제목 규약을 따르지 않는 revert는 못 센다고 함께 출력), 봇 판정에 쓴 패턴.

## 3. 인시던트를 eval로 (E37)

| 단계 | 내용 |
|------|------|
| 1 수집 | 과거 인시던트·revert PR 중 **원인 버그가 사람에게 확인된 것**만 고른다 |
| 2 고정 | 버그를 들여온 커밋의 diff와 "잡았어야 할 발견"(위치·부류)을 기록한다 |
| 3 실행 | 리뷰어 구성(프롬프트·필터·모델·깊이)을 바꿀 때마다 이 세트에 돌린다(사례: 매일) |
| 4 판정 | **점수를 올리지 못한 변경은 버린다**(E37). 깨끗한 PR 세트(N2)의 오경보도 함께 본다 — 재현율만 오르고 오경보가 크게 늘면 채택 보류 |

- 세트가 작으면 판정이 흔들린다는 한계를 적는다. 표본 수를 함께 보고한다.
- eval 채점기 자체의 설계(judge 구성·validity 감사)는 이 하네스의 범위가 아니다. 여기서는 **무엇을 eval로 삼고 언제 돌리고 어떤 결정에 쓰는가**만 정한다.

## 4. circuit breaker 설계 (E11의 빈칸, `[HARNESS]`)

출처는 "revert·인시던트가 오르면 승인을 자동으로 조이는 장치가 아직 없고, 사람 0명 머지를 늘리기 전에 원한다"고 밝혔다. 이 하네스는 그 장치의 **설계 틀**을 제안한다. 출처의 구현이 아니다.

```markdown
| 항목 | 값(사용자가 정함) |
|------|-------------------|
| 감시 지표 | G1 revert율 (+ G2 인시던트율) |
| 창 | 최근 {N}일 롤링 |
| 발동 조건 | 기준선 대비 {+X}%p 초과 또는 절대 {Y}% 초과, 최소 표본 {M} PR |
| 조이는 동작 | 예: Low 등급 사람 0 → 1 / Medium 1 → 2 / 사람 0명 경로 정지 |
| 범위 | 저장소 전체 또는 원인 경로(등급 규칙 ID)만 |
| 해제 조건 | {N}일 연속 기준선 이하 + 사람 확인 |
| 소유자 | 발동·해제 알림을 받고 해제를 승인하는 사람 |
| 수동 우선 | 사람은 언제든 발동할 수 있고, 자동 해제는 없다 |
```

- **조이는 방향만 자동, 푸는 방향은 사람**(`[HARNESS]`).
- 발동 이력을 남긴다 — 어느 규칙 ID에서 회귀가 났는지가 Phase 2 등급 규칙 수정의 입력이다.
- 구현 수단(스케줄 워크플로·ruleset API 등)을 제안할 수 있지만 **만들거나 적용하지 않는다**(INV-1).

## 5. 하지 않는 것

- 점수·성숙도 등급·종합 지수를 만들지 않는다(INV-6).
- "이 지표 체계를 쓰면 revert가 준다"고 약속하지 않는다(X3).
- 개인별 지표를 만들지 않는다 — 인시던트 리뷰는 개인이 아니라 시스템을 본다(E39).
