# 방어 계층 모델 (Layer Model) — Phase 1

리뷰를 "누가 읽었나"가 아니라 **"이 실패를 어느 층이 잡아야 하나"** 로 보는 지도다(evidence E4·E7·E8). 층은 서로를 대체하지 않는다. 각 층은 일부를 잡고 일부를 놓친다는 전제로 짠다.

## 1. 7개 층 + 롤백

| 층 | 이름 | 무엇을 잡나 | 관측 신호(결정론적으로 확인할 것) |
|----|------|-------------|------------------------------------|
| `L1` | PR 전 검증 | 작성자(사람·에이전트)가 실행 가능한 검사를 돌렸고, **새 컨텍스트**의 리뷰가 diff를 봤는가 | CLAUDE.md에 실행 명령(test/build/lint)이 있는가 · 포매터·린터 훅(`.claude/settings.json` hooks, pre-commit) · 로컬 리뷰 커맨드 사용 관례 |
| `L2` | 필수 CI | 린트·타입·테스트·빌드·패키징이 빨강이면 머지 불가 | `.github/workflows/*` 등 CI 정의 · 브랜치 보호의 required status checks · PR 템플릿의 **테스트 방법·되돌리는 방법·위험** 절 |
| `L3` | AI 코드 리뷰 | 저장소 전체와 PR이 밝힌 의도 기준의 정확성 버그 | AI 리뷰어 설치 여부(GitHub App·Action·워크플로) · REVIEW.md 존재·위치 · 깊이 설정 |
| `L4` | 보안 리뷰 | 별도 패스의 보안 결함 | 보안 리뷰 워크플로·Action · 발견이 머지를 막는지 |
| `L5` | 위험 등급 사람 승인 | 위험한 변경에 필요한 사람 판단 | CODEOWNERS · required approving review count · dismiss stale approvals · code owner review 요구 · 등급 라벨·분류 규칙 |
| `L6` | merge queue · 플래그 · 단계 출시 | 최신 main과의 상호작용, 노출 범위 제한 | merge queue 설정 · 기능 플래그 라이브러리·설정 · 채널(내부→단계) 배포 정의 |
| `L7` | 탐지 · 롤백 | 머지 후 회귀 | 배포 없이 끄는 플래그 · 한 단계 롤백 절차 · on-call · 인시던트 리뷰 템플릿에 "어느 층이 잡았어야 했나" 질문 |

## 2. 판정 값 — 4값만 쓴다

| 값 | 뜻 |
|----|----|
| `있음` | 정의 파일·설정을 **직접 확인**했고 머지 경로에 강제된다 |
| `약함` | 존재하지만 강제되지 않는다(예: CI가 있지만 required가 아님, CODEOWNERS가 있지만 code owner review 요구가 꺼져 있음, AI 리뷰 발견을 아무도 답하지 않아도 머지 가능) |
| `없음` | 확인했고 존재하지 않는다 |
| `미확인` | 확인할 수단이 없다(권한·API 접근 불가, 조직 설정 등). **추측으로 채우지 않는다** |

점수·성숙도 단계·백분율로 환산하지 않는다(INV-6).

## 3. 실패 유형 → 잡아야 할 층 매트릭스

사용자가 최근 revert·인시던트·리뷰 누락 사례를 주면 각 사례를 아래처럼 한 줄씩 매핑한다. 사례가 없으면 **대표 실패 유형**만 매핑하고 "사례 기반 아님"을 밝힌다.

```markdown
| 사례/유형 | 실제로 잡은 층 | 잡았어야 할 층 | 그 층이 놓친 이유 | 보완 후보 |
|-----------|----------------|----------------|--------------------|-----------|
| 캐시 키 충돌로 다른 사용자 데이터 노출 | L7(고객 신고) | L3 또는 L5 | 캐싱 경로가 Medium 등급이 아니었음 | 캐싱 경로를 always-human 목록에 |
```

대표 실패 유형(사례가 없을 때 쓰는 출발점):

| 유형 | 1차 층 | 2차 층 |
|------|--------|--------|
| 타입·빌드·포맷 오류 | L2 | L1 |
| 로직 버그(경계값·상태) | L3 | L1(테스트) |
| 인증·권한·주입 | L4 | L5 |
| 최신 main과의 충돌·상호작용 | L6(merge queue) | L2 |
| 사용자 노출 회귀 | L6(플래그·단계 출시) | L7 |
| 정책·CI 파일 약화 | L5(always-human) | L2 |
| 방향·범위 오류(만들지 말았어야 함) | 사람 — PR 이전, 스레드에서 일찍(E39) | — |

## 4. 갭 우선순위

갭은 **"그 층이 없어서 실제로 빠져나간 사례가 있는가"** 순으로 정렬한다. 사례가 없는 갭은 "예방적"으로 표시하고 뒤로 보낸다. 우선순위를 점수로 만들지 않는다 — 근거 사례 수와 blast radius를 나란히 적는다.

## 5. 경계

- 층을 **설치·설정하지 않는다.** 이 문서는 지도다. 무엇을 바꿀지는 Phase 2~5의 제안이고, 적용은 사람이 한다(INV-1).
- CI 파이프라인 자체의 설계(잡 구조·캐시·IaC 정책·릴리스 결정)는 이 하네스의 범위가 아니다. 여기서는 **리뷰 경로에서 CI가 머지를 막는가**만 본다.
