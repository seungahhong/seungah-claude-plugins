# 개입 카드 카탈로그 (intervention catalog)

> Phase 2 제안표가 참조하는 **단일 진실 기준**. 코드 **본문** 층(주석·명명·구조 + 마크업 시맨틱·테스트 설명)만 다룬다.
> 저장소 층(README·CLAUDE.md·의존 그래프·CI)은 측정 모드(score.py) 소관 — 본문 층 개입과 분리.
> 모든 카드는 **게이트 B(개별 승인)** 후에만 적용한다. 승인 없이 파일을 쓰지 않는다. 커밋은 git-harness 핸드오프.
> 인용은 근거 시트(`references/research/EVIDENCE-SHEET.md`) 밖으로 나가지 않는다.

## C0 · 오도/stale 주석 삭제

- **id**: `C0` · **이름**: 오도·stale 주석 삭제/수정 · **우선순위**: **P1** · **대상 축**: 주석
- **무엇을 바꾸나** — 코드와 어긋난 주석을 제거한다(수정이 아니라 삭제가 기본).
  ```
  // FIXME: 실패 시 3회 재시도 (실제 코드엔 재시도 없음)  ← stale
  send(req)
  ```
  →
  ```
  send(req)
  ```
- **근거** — E-C1 `[PRIMARY-2025+ · 2025-04, NeurIPS 2025]` 오도 주석(MDC) **−13.47pp**(구조 변형 3종 결합 −14.04pp에 필적, CoT로도 방어 안 됨). E-C3 `[PRIMARY-2025+ · 2025-12]` 코드-주석 불일치(CCI)는 실측 가능한 결함 유형. 배경 정의 iComment(2007) `[PRIMARY-pre2025]`.
- **동작 위험**: 없음 — 주석은 실행되지 않는다. **삭제는 동작을 깨뜨릴 수 없다.** · **사실성 위험**: 없음(제거이므로 새 주장을 만들지 않음).
- **1급 센서**: 사람 확인 + 코드 대조(주석 진술 ↔ 실제 제어흐름). · **2급 센서**: 빌드/타입체크가 여전히 통과(`tsc --noEmit` / `go build ./...` / `cargo check`) — 코드는 안 건드렸으므로 불변이어야 정상.
- **적용 도구**: 텍스트 편집(주석 블록 제거). 도구 강제 불필요.
- **롤백**: 해당 hunk `git checkout -- <file>` 또는 revert.
- **게이트**: B.
- **거부 조건**: 주석이 **계약·불변식**을 담고 있고 코드가 그와 다르게 동작하면 → 주석이 아니라 **코드가 버그일 수 있다.** 삭제하지 말고 "코드-주석 불일치, 어느 쪽이 진실인지 판단 필요"로 **사람에게 보고**(C1로도 자동 승격 금지).

## C1 · 계약·불변식 주석 추가/수정

- **id**: `C1` · **이름**: 계약·불변식 주석 추가/수정 + **'왜/맥락' 주석(comment-gap)** · **우선순위**: **P3** · **대상 축**: 주석
- **무엇을 바꾸나** — 코드 대조로 검증된 전제/불변식/에러 조건만 문서화한다.
  ```
  def withdraw(acct, amt): ...
  ```
  →
  ```
  # 계약: amt > 0 이고 acct.balance >= amt (아니면 InsufficientFunds raise)
  # 불변식: 정상 반환 후 acct.balance >= 0
  def withdraw(acct, amt): ...
  ```
- **근거** — E-C2 `[PRIMARY-2025+ · 2025-12, ICSE 2026]` 주석은 **양방향** 인과 인자(품질이 관건)이며 Javadoc/inline/multiline을 별개 개념으로 내재화. ⚠️ `−90%~+67%`는 CAV 임베딩 개입치라 텍스트 추가/삭제 효과로 **인용 금지** — 방향·상한 증거로만. E-C5 `[PRIMARY-pre2025 · 2024-06 · 배경]` 최상위 모델도 생성 주석의 약 **20%**가 검증가능하게 부정확. **양(positive) 효과 크기 없음(추론)** — O-3(추가의 대칭 효과 미확립).
- **동작 위험**: 없음(주석 미실행). · **사실성 위험**: **~20~45%** — E-C5 약 20% 부정확, E-C4 `[PRIMARY-2025+ · ICSE 2025]` 특화 파인튜닝 모델의 주석 수정도 35~45%가 틀림 → **자동 적용 금지**.
- **1급 센서**: 코드 대조(주석 각 절 ↔ 실제 분기/예외). · **2급 센서**: 가능하면 **document testing** — 주석에서 실행 가능한 검사를 도출해 pass/fail 채점(E-C5, ROC-AUC 0.67·정확도<0.8 필터 시 부정확 주석 46% 제거). 테스트 LLM 자체도 환각 가능하므로 보조 신호로만.
- **적용 도구**: 텍스트 편집. 사실성 위험이 실행으로 완전 해소되지 않으면 **제안만** 하고 사람 확인.
- **롤백**: hunk revert.
- **게이트**: B.
- **거부 조건**: 코드 대조로 검증 불가한 추측성 주장(성능·의도·미래 계획)은 추가하지 않는다. 검증 실패한 계약은 추가 대신 **불확실 표기 후 사람에게 질의**.

### C1-gap · '왜/맥락' 주석 (comment-gap seed · opt-in · 필수 아님)

census의 `C7_SILENT_HANDLER`·`C8_MAGIC_NUMBER`·`C9_REGEX_LITERAL`은 **코드만으로 '왜'를 알기 어려운 지점**이다. 이 지점에 한해 계약 주석과 같은 게이트로 **'왜/맥락' 주석을 opt-in 추가**한다.

- **무엇을 쓰나** — **what이 아니라 why**: 의도·외부 제약(스펙·API 한계·호환)·우회 이유·단위/출처. 코드를 다시 말로 옮기는 주석은 추가하지 않는다.
  ```python
  except ValueError:
      pass
  ```
  →
  ```python
  except ValueError:
      # 업스트림이 빈 payload를 보낼 때만 발생한다. 재시도는 무의미해서 흘려보낸다.
      pass
  ```
- **근거** — E-CG1 `[report-only]` 2404.03114의 null 결과는 *이미 읽히는* 코드에 문서를 더한 경우이고, comment-gap은 **코드에 아예 없는 정보를 보충**하는 별개 사례다. 그래도 이득은 **사람 이해 + 비파생 맥락**으로만 말하고 "LLM 성공률 +N%"로 말하지 않는다(효과=추론·O-3).
- **동작 위험**: 없음. · **사실성 위험**: C1과 동일(~20~45%) → **사람이 사실성을 검증**하고, 자동 생성 주석을 사실로 단정하지 않는다.
- **점수 무관**: 주석 개수·밀도는 **어떤 census 수치에도 가점되지 않는다**(볼륨 가점 = Goodhart). 후보를 전부 채우는 것이 목표가 아니다.
- **대안 우선**: 매직 넘버는 주석보다 **이름 있는 상수**가 나을 수 있다(그 경우 C2 리네임 규약을 따른다).
- **거부 조건**: 왜인지 사람도 모르면 추측해서 쓰지 않고 **"확인 필요"로 사용자에게 질의**한다. 침묵 예외가 사실은 버그로 보이면 주석으로 덮지 말고 **결함으로 보고**한다.

## C2 · 안전 리네임

- **id**: `C2` · **이름**: 무의미·오도 식별자 안전 리네임 · **우선순위**: **P2** · **대상 축**: 명명
- **무엇을 바꾸나** — 의미 단서 없는 식별자를 본문이 하는 일과 일치하는 이름으로 바꾼다.
  ```
  d = fetch()          # d = 활성 사용자
  for x in d: notify(x)
  ```
  →
  ```
  active_users = fetch()
  for user in active_users: notify(user)
  ```
- **근거** — E-N1 `[PRIMARY-2025+ · 2025-10]` 명명 채널 억제 시 class-level accuracy **−11~29pt**(통제 perturbation ablation → 인과 정당). E-N3 `[PRIMARY-2025+ · 2025-04, NeurIPS 2025]` 식별자 NL 단서 의존(LiveCodeBench 평균 −8.20pp) — ⚠️ 효과 크기는 **기존 이름이 이미 얼마나 좋은지에 의존**(CRUXEval −2.38pp). E-N4 `[PRIMARY-2025+ · 2025-03]` 좋은 함수명은 구현 복원 수준의 의미를 운반. ⚠️ 이들은 **제거 ablation(감소분)** 이므로 "좋은 이름을 새로 붙이면 같은 크기로 오른다"는 **대칭 가정 불가(O-3)** → 개선 방향 효과 크기 없음(추론).
- **동작 위험**: 참조/컴파일 깨짐 — E-A4 `[PRIMARY-2025+ · 2026-05]` 자동 리팩터의 주 실패는 논리 오류가 아니라 **컴파일 가능성 저하**. · **사실성 위험**: E-N4 false positive — LLM은 **부정확한 이름도 메워서 맞춘다** → **LLM의 코드 이해 성공을 명명 오라클로 쓰지 말 것.** 판정은 이름↔본문 대조(구조적 검사).
- **1급 센서**: **컴파일/타입체크 + 참조 완전성** — 리네임 전후 심볼 참조 수 일치를 LSP로 확인, `tsc --noEmit` / `pyright` / `go build ./...` / `cargo check` 재통과. · **2급 센서**: 텍스트 grep(`git grep -n '\bd\b'`) — ⚠️ 스코프/섀도잉을 구분 못 하므로 advisory only, 절대 grep 치환으로 적용하지 않는다.
- **적용 도구**: **AST/LSP 기반 rename만** — Python: rope·pyright/LSP, TS/JS: ts-morph·tsserver LSP rename, Go: gopls rename, Rust: rust-analyzer, Java: IDE LSP. **도구가 없으면 적용하지 말고 제안만.**
- **롤백**: 동일 도구로 역방향 rename(새→옛). safe by construction(E-A5: 잘못된 연산은 그냥 실패).
- **게이트**: B.
- **거부 조건**: **공개 API·직렬화 키·DB 컬럼·외부 계약(설정 키·이벤트 이름·리플렉션 참조)** 에 노출된 심볼 — 컴파일러가 못 잡는 **런타임 파괴**를 일으킨다. AST/LSP 스코프 밖 문자열·직렬화 경계는 반드시 **사람 판단**(E-A5: developer supervision is not optional).

## C3 · 구조 리팩터

- **id**: `C3` · **이름**: 구조 리팩터(경계·응집·추출) · **우선순위**: **P4 · 기본 OFF · opt-in** · **대상 축**: 구조
- **무엇을 바꾸나** — 뒤섞인 책임을 **최소 단위**로만 분리한다(통째 재작성 금지).
  ```
  def handle(req):
      # 검증 + 파싱 + 저장이 한 덩어리
      ...
  ```
  →
  ```
  def handle(req):
      valid = validate(req)      # 추출된 최소 단위만
      return persist(parse(valid))
  ```
- **근거** — E-S1 `[PRIMARY-2025+]` 강한 정량 델타는 전부 **툴 측 그래프/인덱스** 효과지 **본문 수정 측정이 아니다.** 본문 구조 개선 효과는 **추론이지 측정이 아니다 → 효과 크기 없음(추론)**. ⚠️ ARISE는 `+4.7pp` end-to-end만 인용(R@1 수치는 REFUTED). E-S2 `[PRIMARY-2025+ · 2026-03]` 구조는 최대 실패면 — micro 53.5% → **multi-step 20.6%**, 의존성 통제 4.3%, **64/483(13.3%)이 기능 테스트 통과하고도 구조 오라클 실패**.
- **동작 위험**: **높음** — E-A1 `[PRIMARY-2025+ · 2026-02]` 안전 재작성을 명시해도 **19~35%가 기능적 비등가**. E-A3 단순화조차 ≈26% 비등가(복잡도에 비례, 큰 함수 통째가 가장 위험). · **사실성 위험**: 낮음(주석/이름이 아닌 제어흐름 변경).
- **1급 센서**: 테스트 + 컴파일 **+ 사람 diff 리뷰(필수)**, 그리고 **테스트가 없거나 약하면 행위 센서**(영향 표면을 실제 실행·렌더해 baseline과 대조 — standalone 슬라이스/MSW/dev 서버/CLI, `verify`·`run` 스킬) — ⚠️ **"테스트 통과 = 동작 보존"이 아니다**: E-A2 테스트가 비등가의 **≈21%를 놓친다**(HumanEval 20.72·MBPP 21.65·APPS 22.41%). 행위 실행도 등가 *증명*은 아니라 상한은 UNVERIFIED이지만 정적 diff보다 훨씬 강한 회귀 포착이다. 등가 증명 불가를 명시하고 **감수 여부는 사람이 최종 결정**(에이전트가 대신 보류하지 않는다). `pytest` / `go test ./...` / `cargo test` + 리뷰어 diff 정독. · **2급 센서**: 가능 시 differential fuzzing(E-A2 권고), reward-hacking 감시(E-M1·E-M2, trace만으로는 28% 놓침).
- **경계 주의(격리 센서 맹점 — C2 line 74 대칭·필수)**: 구조 이동/분할이 **공개 API·파일 기반 라우트·직렬화/lazy-chunk 경계·동적/리플렉션 import·외부 소비자**를 건드리면 격리 렌더 센서(standalone/MSW)는 이를 **관측하지 못한다**(격리 렌더는 통과해도 실제 앱은 404·소비자 import 깨짐 가능 — 컴파일러도 못 잡는 런타임 파괴). 이런 이동은 센서를 **실제 라우트/소비자를 구동하는 관측으로 승격**하거나, 불가하면 **UNVERIFIED로 두고 사람 판단으로 escalate**한다(리네임 C2의 공개 계약 거부 조건과 대칭). 판정을 격리 렌더의 green으로 올리지 않는다. — 이는 거부가 아니라 *더 강한 센서 요구 + 사용자 결정*이다(결정 권한 유지).
- **적용 도구**: LSP의 extract/move 리팩터 API가 있으면 그것으로, **없으면 최소 단위 수작업 편집**(통짜 재작성 금지·한 번에 한 단계·행위 센서 필수) — 리네임(C2)과 달리 도구 부재가 "제안만" 강등 사유가 **아니다**. 어느 경우든 에이전트 자율 적용 금지(E-S2: 의존성 통제 통과율 4.3%) — 매 단계 게이트 B + 사람 diff 리뷰.
- **롤백**: 전체 diff `git revert`.
- **게이트**: B **+ C3 전용 사람 diff 리뷰 필수**. 위험은 경고하되 **감수 결정은 사용자** — opt-in·게이트 B 승인된 C3를 에이전트가 조용히 보류·강등하지 않는다(새 차단 요인은 사용자에게 escalate).
- **거부 조건**: (1) **어떤 등가성 센서도 없을 때만 제안 보류** — 자동 테스트 부재는 그 자체로 거부 사유가 아니다(테스트는 애초에 약한 오라클, ≈21% 누락). 테스트가 없으면 **행위 센서로 승격**(영향 표면 실제 실행·렌더로 baseline 대조; standalone 슬라이스/MSW/dev 서버/CLI, `verify`/`run`). 테스트·컴파일/타입체크·행위 실행·diff 리뷰 **어느 것으로도** 등가를 관측할 수 없을 때만 보류하고, 그조차 조용히 거부하지 말고 사용자에게 "미관측 진행/센서 먼저/건너뛰기?"로 결정을 넘긴다, (2) **큰 함수 통째 재작성**, (3) **다단계 연쇄 변경**(E-S2 multi-step 20.6% — 한 번에 한 최소 단위만).

## C4 · 테스트 설명·셀렉터

> 대상 축: `tests`. 근거 정본: [`research/body-legibility/semantic-markup-tests.md`](research/body-legibility/semantic-markup-tests.md) E-TL1·E-TL2.
> **지배 단서**: 올바른 설명의 LLM 이해 이득은 유의하지 않고 **오도 설명만 측정 가능하게 해롭다**(비대칭). 그래서 이 카드는 **설명을 늘리는 개입이 아니라 오도·모호를 걷어내는 개입**이다.

### C4a · 오도·모호 테스트 제목 교정 (**P1** · 위험 0 · ON)

- **무엇을 바꾸나** — census `TL1_VAGUE_TEST_TITLE` 후보의 제목을 **대상·동작·기대결과**가 드러나게 고친다. 오도(본문과 다른 주장) 제목은 **교정 우선**.
  ```js
  it('works', () => { expect(withdraw(acct, 200)).toThrow(); });
  ```
  →
  ```js
  it('rejects a withdrawal larger than the balance', () => { ... });
  ```
- **근거** — E-TL1 `[PRIMARY-pre2025 · 배경]` "incorrect documentation can greatly hinder code understanding, while incomplete or missing documentation does not seem to significantly affect…". 제목↔본문 괴리는 **컴파일러가 검증하지 않는** 실패 모드다.
- **동작 위험**: 없음(테스트 이름은 로직이 아니다). ⚠️ 단 **이름으로 테스트를 선별 실행하는 CI 필터**(`-k`·`--grep`·tag)가 있으면 **선택 집합이 바뀐다** — 리네임 전 CI 설정을 확인하고, 걸리면 사람에게 보고한다.
- **1급 센서**: 테스트 스위트 재실행(수집 개수·통과 개수 불변). · **2급 센서**: 사람이 본문을 읽고 제목이 실제 검증 내용과 맞는지 대조.
- **거부 조건**: 본문이 **무엇을 검증하는지 읽어 확인하기 전에는 리네임하지 않는다**(잘못된 제목으로 바꾸면 오도를 새로 만든다). **자동 어서션·오라클 생성 금지** — 테스트를 LLM 최적화 대상으로 쓰면 구현을 굳혀 버그를 초록으로 은폐한다(green-locks-bug).

### C4b · 비의미 셀렉터 → `getByRole`류 이관 (**P4** · **opt-in** · 기본 OFF)

- **무엇을 바꾸나** — `getByTestId`/CSS/xpath 셀렉터를 `getByRole`/`getByLabelText`류로 이관한다.
- **근거** — E-TL2: refactor-robust는 **벤더 관용(MEDIUM)**이고, **"AI 이해를 향상한다"는 근거는 ABSENT**다. 이관의 이득은 사용자 관점 테스트·마크업 churn 내성으로만 말한다.
- **동작 위험**: 있음 — accessible name 계산에 의존해 ARIA/label 변경에 깨지고, 셀렉터가 **다른 요소를 잡을 수 있다**(테스트가 조용히 다른 것을 검증하게 된다).
- **1급 센서**: 이관 전후 **같은 테스트가 같은 이유로 통과/실패하는지** 관측(의도적으로 대상을 깨뜨려 red가 나는지 확인 — 초록만으로 판정 금지).
- **거부 조건**: **`getByRole` green을 a11y 보장으로 취급 금지**(axe 대체 아님 — `<div role="button">`은 통과하면서 키보드·포커스를 잃는다). 이관은 접근성 개선이 아니라 셀렉터 변경일 뿐이다.

## C5 · 마크업 시맨틱

> 대상 축: `markup`. 근거 정본: 같은 dossier E-MK1~E-MK3.
> **지배 단서**: 랜드마크·`<button>` vs `<div onclick>`를 **격리해 LLM 이해 델타를 잰 연구는 없다**(O-6). 유일한 대조는 표현 형식이고 승자가 모델 역량에 따라 뒤집힌다 → **개선은 접근성·사용성 개선으로만 말한다.**

### C5a · native 우선 교정 (**P2** · 위험 낮음 · ON)

- **무엇을 바꾸나** — census `MK2_REDUNDANT_ROLE`(native가 이미 주는 `role=`)를 **제거**하고, `MK3_IMG_MISSING_ALT`에 **사람이 의미를 확인한** `alt`를 넣는다.
  ```html
  <button role="button">저장</button>   →   <button>저장</button>
  ```
- **근거** — E-MK2 `[ESTABLISHED · W3C/MDN]` 'First rule of ARIA'. 잘못된 ARIA는 native 시맨틱을 덮어써 **no-ARIA보다 나쁠 수 있다**.
- **동작 위험**: 낮음(중복 role 제거는 의미 불변). alt 추가는 렌더에 영향 없음.
- **1급 센서**: 렌더 스냅샷·기존 테스트 통과 + **사람 확인**(alt 문구가 실제 이미지 의미와 맞는가).
- **거부 조건**: **자동 ARIA/alt 생성 금지** — confident-but-wrong이 실증된 벡터다(자동 remediation overlay가 focus order를 파괴한 사례). 이미지의 의미를 모르면 채우지 말고 **사람에게 질의**. `role=`이 native와 어긋나게(의도적으로) 쓰인 경우는 제거가 아니라 **보고**.

### C5b · `<div/span onClick>` → `<button>`/`<a>` 승격 (**P4** · **opt-in** · 기본 OFF)

- **무엇을 바꾸나** — census `MK1_NONSEMANTIC_CLICK` 후보를 native 인터랙티브 요소로 승격한다(키보드·포커스·역할을 자동 획득).
- **근거** — E-MK1: 접근성 이득은 표준·명확하나 **AI 이해 이득은 격리 근거 없음**. 이 카드를 "AI가 더 잘 읽는다"로 팔지 않는다.
- **동작 위험**: **있음** — `<button>`은 기본 스타일·`type="submit"` 기본값·이벤트 전파·폼 제출 동작이 `<div>`와 다르다. 레이아웃이 깨지거나 **폼이 예기치 않게 제출**될 수 있다.
- **1급 센서**: **행위 센서 필수** — 영향 화면을 실제 렌더해 클릭·키보드(Enter/Space)·포커스 이동·레이아웃을 baseline과 대조(`verify`·`run` 스킬). · **2급 센서**: 스냅샷 diff.
- **판정 상한**: **UNVERIFIED**(렌더 관측도 등가 증명은 아니다).
- **게이트**: B **+ 사람 diff 리뷰**. 위험은 경고하되 **감수 결정은 사용자** — opt-in·승인된 C5b를 조용히 보류·강등하지 않는다(새 차단 요인은 escalate).
- **거부 조건**: 한 번에 한 요소씩(일괄 치환 금지). 스타일 회귀를 관측할 수단이 전혀 없으면 사용자에게 "미관측 진행/센서 먼저/건너뛰기?"로 결정을 넘긴다.

## 제안 랭킹 규칙

Phase 2 제안표는 각 개입 후보를 **위험조정 기대이익**으로 정렬한다:

```
위험조정 기대이익 = (근거 강도 × 효과 방향) ÷ (동작 위험 + 사실성 위험)
```

- **근거 강도**: SOURCE-TIER + 효과 크기(측정 > 추론). 측정된 감소분(제거 ablation)은 방향 근거로 쓰되 개선 방향은 **추론**으로 감쇄한다(O-3).
- **효과 방향**: 오도 제거(확실한 +) > 검증된 명료화 > 미검증 추가.
- **분모**: 동작 위험 + 사실성 위험. C0은 분모≈0이라 효과 크기가 작아도 최상위(P1이 1순위인 이유 = 위험 0·확실). C3는 분모가 최대라 효과가 추론이면 최하위(P4가 마지막인 이유).
- **동률 처리**: 기대이익이 같으면 **P 번호가 낮은 쪽 우선**(P1 > P2 > P3 > P4).
- **전체 서열(개입 클래스 통합)**: `C0(P1) · C4a(P1)` → `C2(P2) · C5a(P2)` → `C1/C1-gap(P3)` → `C3 · C4b · C5b(P4 · 전부 opt-in)`.
  P1 두 카드는 **삭제·교정이라 분모≈0**이고, P4 세 카드는 **동작 위험이 실재하고 효과가 추론**이라 마지막이다.
- **축 대응**: `naming→C2` · `comments→C0/C1(+C7~C9 seed)` · `structure→C3` · `tests→C4` · `markup→C5`. 사용자가 고르지 않은 축은 census를 돌리지도 않는다.
- **스코프 가드**: 사용자가 Phase 0에서 선택한 개입 클래스 **밖**의 후보는 제안표에 점수를 매기지 않고 **"추가 안 함(스코프 밖)"** 으로 표기하며, **확장 여부를 사용자에게 문의**한다(임의 적용 금지). 이 플러그인은 등급이 아니라 **census + 개입 제안 + 승인 후 적용**만 낸다.
